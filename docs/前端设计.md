# POOL 前端设计

## 1. 范围与设计状态

本文负责页面路由、导航、组件拆分、前端目录、数据归属、播放器交互及 UI 风格。当前请求层与统一业务 hooks 的交付见 [第四阶段文档](开发阶段/04-请求层与业务查询整理.md)。

当前已落地完整桌面交互、真实账号、网易云个人／房间播放、数据库喜欢、Socket.IO 房间和持久历史；第五阶段交付见 [真实一起听与房间页面整理](开发阶段/05-真实一起听与房间页面整理.md)。音乐交付见 [第三阶段文档](开发阶段/03-网易云音乐与喜欢列表持久化.md)，账号交付见 [第二阶段文档](开发阶段/02-基础后端与账号系统.md)，房间总结已接通真实 AI 请求链路，验证边界见 [第七阶段文档](开发阶段/07-AI房间总结.md)。仅面向桌面浏览器，不做移动端适配，顶部四个入口为搜索、喜欢、一起听、设置。

账号由 Better Auth 通过 Cookie Session 管理，前端同步安全用户投影。音乐、喜欢、大厅、创建和历史通过 src/lib/api-client.ts 的 HTTP hooks；房间通过独立 Socket 客户端与页面作用域 store。AI 使用 @ai-sdk/react 原生流式传输。音量以 pool:player:volume 保存；应用不依赖本地曲库、音频或封面文件，缺少封面时使用中性色块。

## 2. 页面路由表

采用 Next.js App Router。`(auth)`、`(app)` 只用于布局分组，不进入 URL；所有业务页面必须登录，登录和注册入口除外。

| URL                     | 页面文件（相对 src/app）              | 导航归属 | 内容与访问规则                                                  |
| ----------------------- | ------------------------------------- | -------- | --------------------------------------------------------------- |
| /                       | page.tsx                              | 无       | 草案：已登录跳 /search，未登录跳 /login，不额外做营销首页       |
| /login                  | (auth)/login/page.tsx                 | 认证     | 邮箱＋密码登录，支持安全的站内 returnTo                         |
| /register               | (auth)/register/page.tsx              | 认证     | 邮箱＋密码注册；不主动新增第三方登录和找回密码流程              |
| /search                 | (app)/search/page.tsx                 | 搜索     | 选择音源、输入关键词、查看结果、播放或收藏                      |
| /likes                  | (app)/likes/page.tsx                  | 喜欢     | 最多 500 首、播放、取消／清空喜欢、导入网易云歌单 |
| /rooms                  | (app)/rooms/page.tsx                  | 一起听   | 房间大厅、搜索、创建、我的房间、进入房间历史                    |
| /rooms/[roomCode]       | (app)/rooms/[roomCode]/page.tsx       | 一起听   | 实时听歌房、加入密码、成员、上台、歌词、聊天                    |
| /rooms/history          | (app)/rooms/history/page.tsx          | 一起听   | 本人最多 50 条房间历史，删除本人凭证                            |
| /rooms/history/[roomId] | (app)/rooms/history/[roomId]/page.tsx | 一起听   | 真实房间详情、生成或查看共享总结                                |
| /settings               | (app)/settings/page.tsx               | 设置     | 当前账号、退出；主题等本地偏好按实际首版范围提供                |

静态 `/rooms/history` 不作为 roomCode；系统生成的房间号带固定前缀，避免与页面路径冲突。活动房使用 code，历史详情使用 roomId，结束房不再作为实时房间加入。

搜索示例：`/search?source=netease&q=ALIVE`。音源、已提交关键词及适合分享的筛选进入 URL；实时进度、密码、未发送消息、用户凭据不进入 URL。offset 可随搜索分页维护，搜索和喜欢跟随页面滚动，滚动位置无需编码到地址；房间页只在内部内容区域滚动。

未登录访问业务页跳至登录；会话失效时清理用户私有缓存、停音并断开 Socket，再进入登录页。returnTo 仅允许站内路径。页面布局鉴权不替代 API 或 Socket 鉴权。

## 3. 导航与全局布局

### 3.1 桌面布局

```text
┌────────────────────────────────────────────────────────────┐
│ POOL        搜索    喜欢    一起听    设置             头像 │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                     当前业务页面                           │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 封面 / 歌曲       播放控制 / 进度          音量 / 队列      │
└────────────────────────────────────────────────────────────┘
```

- 顶部导航固定在视口顶部，高度 60px，不随页面滚动；主体预留同等顶部空间，避免遮挡内容。导航选中项为黑色文字与下方 #42a5f5 横线，不使用选中底色。房间详情与历史页都归属“一起听”；弹窗遮罩及内容层级高于导航。
- 底部播放器固定高度 96px，内部内容使用居中容器统一排版；页面不强制保留无滚动条时的右侧占位，导航和播放栏按视口宽度固定，切换有无页面滚动条时不发生横向跳动。打开播放列表使用仅锁定焦点、不锁定页面滚动的 Sheet，避免移除页面滚动条时改变导航和播放栏位置；播放列表打开不改变播放栏的横向位置或 padding。普通页面为播放栏预留空间，内容不被遮挡。
- 播放栏封面为 49×49px，个人主播放按钮为 33×33px，三区间距 35px；个人控制按钮与进度之间留 6px，房间操作与进度之间留 9px，元素尺寸与栏高配套。
- 普通页建议最大内容宽度 1,280px；房间页充分使用宽度，可扩展至 1,600px。
- 个人音频控制器放在 `(app)/layout` 的常驻客户端边界；房间连接、音频控制器和播放器仅挂载在 `/rooms/[roomCode]` 页面内。
- 离开房间页即退出当前房间：停止房间音频、取消加载与重连、移除订阅并清空房间快照，不跨页面保留房间播放器。退房不等于解散房间，不删除用户房间歌单或历史记录。

## 4. 页面组成与操作

### 4.1 搜索

- 上方仅放音源选择、搜索输入和搜索按钮。当前主搜索接通 netease 匿名真实资料，bilibili 明确“暂未接入”，不伪造空搜索结果。
- 支持按 Enter 提交，关键词不为空才请求；输入阶段不直接为每次按键请求外部源。
- 结果以紧凑歌曲行展示：封面、标题、作者、时长、收藏。使用 offset + limit 查询、加载更多；结果总数未知时不伪造为 0。
- 搜索与喜欢列表默认透明底，hover、键盘聚焦和当前播放项为白底；标准行高 60px，抽屉紧凑行高 56px，虚拟列表估算行高与实际 CSS 一致。
- 搜索和喜欢列表跟随页面滚动，不设置固定高度或独立滚动条；长列表使用 window 虚拟化并测量列表起点。房间抽屉的紧凑列表保留容器滚动。
- 个人播放列表和本人房间歌单超过 50 首时使用 TanStack Virtual，复用抽屉现有滚动容器，不额外嵌套滚动条；队列行高统一为 63px，估算值与 CSS 共用配置。拖动源和焦点行保持挂载，拖拽使用完整队列预览顺序，落下后提交一次完整列表位置；取消时恢复，期间收到不同的队列顺序时放弃旧排序。
- 行主操作为个人播放。
- 显示 source 只为区分来源；同源搜索结果不必每行重复醒目徽章。混合队列中来源可见。
- 搜索为空显示初始输入态；无匹配、上游不可用和能力未支持分别展示，不共用“暂无数据”。

### 4.2 喜欢

- 标题“喜欢”旁显示 `已收藏 / 500`；工具栏提供播放和导入歌单，不增加重复说明文案。
- 喜欢保存于 PostgreSQL，页面一次读取最多 500 首完整集合供播放及喜欢态使用；HTTP 接口同时支持分页。默认添加时间倒序，取消收藏后从查询结果移除。达到上限时禁用新增并给出具体提示，容量仍由服务端决定。
- 导入 Dialog 包含音源选择与歌单链接，目前只提供网易云音乐选项；提交 source 和 url，提交期间显示任务状态。结果按实际接口反馈新增、重复、失败和因容量跳过的数量，未知数量不编造为 0。平台链接校验失败留在表单。
- 清空喜欢使用 Alert Dialog 确认，提交期间禁止重复操作；useClearLikes 内置缓存刷新，成功后通过页面回调关闭确认框，失败显示 toast 并保留重试入口，不清空正在播放的队列。导入通过 mutate({ source, url }) 传入，保留输入弹窗，结果统计使用 toast。
- 音乐最多 500 首，按项目概览使用 TanStack Virtual；数据库排序和分页先确定，虚拟化不改变真实排序，也不代替接口分页。

### 4.3 一起听大厅

- 头部为房间搜索、创建入口，提供“房间历史”次级入口；不新增第五个全局导航项。
- 搜索框匹配房间名、标签或完整房间号；标签在房间卡片展示，不提供独立的标签筛选按钮。
- 我的有效房间可固定在列表前，公开房以紧凑卡片展示房间名、标签、房主、人数和加入操作。卡片默认透明底，hover、聚焦及按下时使用白底，背景立即切换，不做缓入缓出过渡。
- 密码房通过房间号查找或自己的房间入口进入，不显示密码，也不把密码写进分享地址。
- 创建 Dialog 包含名称、标签、人数、上台人数和可选密码，复杂规则交给表单错误反馈。
- 创建成功进入 `/rooms/[roomCode]`，页面经 Socket 真正加入；不能把 HTTP 创建成功直接显示为“已加入”。

### 4.4 实时房间

```text
┌───────────────────────────────────────────────────────────┐
│ 房间名 / 人数                  设置（房主） / 离开房间    │
├──────────────────────────────────┬────────────────────────┤
│ 成员与上台顺序                   │                        │
│ ──────────────────────────────── │       聊天消息         │
│ 当前歌曲 / 封面                  │                        │
│             歌词                 ├────────────────────────┤
│                                  │ 输入消息 / 发送        │
├──────────────────────────────────┴────────────────────────┤
│ 当前曲目      只读进度 / 切歌或投票       音量 / 我的歌单  │
└───────────────────────────────────────────────────────────┘
```

- 初次加载先展示加入状态；需要密码时显示密码表单，加入成功才创建房间数据投影。
- 房间页只提供一个“离开”按钮返回大厅并执行退房清理，不重复显示返回图标，不提供手动重新连接按钮；加载及密码输入阶段也使用同一个离开语义。
- 成员区使用同一面板、两份独立列表：“房间成员”标题右侧用 shadcn/ui AvatarGroup 显示全体成员；下方仅按 stageIds 展示上台成员，头像在上、名称在下，当前播放者另显“播放中”图标与文字。听众不进入上台列表，上下台不改变房间头像组的成员数量。
- 本人通过面板按钮上下台；房主可在上台成员头像旁让其他成员下台，在房间设置的成员管理中移出成员。两类列表分别读取房间成员与上台顺序，不复用混合排序列表。
- 房间设置中的密码操作使用横向三个选项，分别为保持不变、设置新密码和移除密码；选中后直接显示对应状态，不使用下拉框。
- 房间页使用导航与播放栏之间的固定可用高度，页面本身不可滚动；聊天、歌词和成员列表在各自容器内滚动，头部、聊天输入与播放操作持续可见。消息自动滚动仅作用于消息容器。
- 我的房间歌单使用双列 Sheet：左侧选择音源，点击 submit 按钮或按 Enter 提交关键词搜索并加歌；右侧展示本人的歌单、导入喜欢、打乱、清空和拖拽手柄；两列独立滚动。拖动按 itemId 与目标位置提交房间命令，不改变当前节目、起播锚点或播放版本；断线重连期间禁用修改。每人最多 500 首，导入填满剩余额度，不将所有成员曲目做成可随意编辑的共享列表。
- 房间播放进度只读，不响应拖动；当前播放者显示“切歌”，其他成员显示投票数量和本人是否投过票，无暂停操作。
- 自动播放限制显示一个清晰的“启用声音”操作；它只解锁本地音频，不暂停或改变全房状态。
- 重连中保留最后画面但禁用依赖连接的命令，重新拿到快照后校准；被踢、切换房间、房间结束分别显示一次原因并清理旧投影。
- 聊天按消息 ID 去重，保留最近 200 条客户端消息；用户向上读消息时不强制滚到底部，有新消息时给出回到底部入口。
- 聊天单条最多 120 字符，每用户每 10 秒最多 5 条；超限显示等待提示，不自动重发。服务端每房最多保留最近 10,000 条，与客户端 200 条和 AI 最新 200 条完整消息分别计算。
- 总结使用服务端保留的最新 200 条完整聊天，原始聊天不在历史详情对外展示，房间结束满 7 天清理。
- 房主离开后的身份流转沿用旧项目；房主只拥有活动房间操作权限，结束后的总结不区分房主与普通参与者。

### 4.5 真实房间历史与共享总结

- 历史列表使用透明底紧凑行，hover 与键盘聚焦时为白底，缩小条目内边距和行间距；展示房间名、最近进入时间、结束状态和有效期，最多 50 条。删除前说明会失去房间详情访问权限，其他成员历史不受影响。
- 活动房记录可返回当前房间；已结束记录进入归档页，不尝试 Socket 加入。
- 详情页头并列展示房间名与标签，下方展示结束时间和参与者 AvatarGroup；最多直接展示 8 位头像，其余以 +N 收起，到期日期在右侧弱化展示。参与者来自成功加入记录，包含已离开或删除本人历史的成员，使用账号当前昵称和头像。
- 页头下方用一行显示参与人数、播放记录数和聊天条数，不拆成数据卡片。参与人数按用户去重；播放与聊天统计当前保留记录，达到上限时分别显示 500+／10000+，不声称是完整累计值。
- 详情通过真实凭证接口读取房间资料、参与者和互动计数，不提供原始聊天。下方保留原有总结区域：已结束房间显示生成按钮及流式总结；活动房间提示结束后生成。
- 历史凭证被删除、淘汰或归档到期后，详情返回 403 ROOM_HISTORY_REQUIRED；页面显示真实错误与返回历史入口。
- 总结每房共享一份，生成中其他成员通过 GET 每两秒查询；成功后只展示持久正文，失败可手动重试，不提供删除／重新生成。关闭页面只停止接收，服务端继续，返回后查看最终结果，不恢复中断的流。

### 4.6 设置与认证

- 设置仅呈现已落地的账号信息、退出与本地偏好
- 登录使用邮箱密码，注册填写昵称、邮箱和 8～128 位密码，成功直接登录；不显示邮箱验证或邮件找回入口。会话有效 7 天并自动续期，无“记住我”。设置已接通昵称和密码修改；改密需要当前密码并撤销其他会话。密码不写 URL、日志和持久 store。
- AccountSessionProvider 使用 Better Auth 客户端作为会话来源，同步安全投影到现有页面；聚焦和每 300 秒刷新，换号或失效时清理查询、停音和卸载房间。请求失败显示重试。

## 5. 组件拆分与职责

```text
RootLayout
├─ GlobalStyles
└─ AppLayout（业务页面共享；各页面入口独立检查服务端会话）
   └─ ClientProviders
      ├─ QueryProvider
      ├─ PersonalAudioController（个人播放常驻）
      └─ AppShell
         ├─ TopNav
         ├─ PageContent
         │  └─ RoomPage（仅房间路由）
         │     └─ useRoomSession（连接与页面作用域 Zustand 快照）
         │        ├─ RoomContent
         │        ├─ useRoomAudio（加入成功后启用，取消旧媒体加载）
         │        └─ RoomDock
         ├─ PersonalPlayerDock（加入房间期间隐藏）
         └─ GlobalFeedback
```

| 组件组     | 拆分建议                                                                                      | 职责边界                                                                             |
| ---------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 布局       | AppShell、TopNav、UserMenu                                                                    | 导航与尺寸，不直接解析音源资料                                                       |
| 音乐       | SourceSelect、SearchForm、TrackList、TrackRow、TrackActions                                   | 接收统一 TrackDto 和操作回调，不包含平台专属字段判断                                 |
| 喜欢       | LikesToolbar、ImportPlaylistDialog                                              | 收藏容量及导入反馈，API 逻辑在业务 hooks                                             |
| 大厅       | RoomSearch、RoomList、RoomCard、CreateRoomDialog                                              | HTTP 房间摘要，不保存当前房间在线快照                                                |
| 房间       | RoomHeader（含设置）、RoomParticipants、RoomNowPlaying、RoomChat、RoomDock                    | 订阅所需字段，权限来自当前会话和快照                                                 |
| 队列       | PersonalQueueSheet、RoomPlaylistSheet                                                         | 房间抽屉复用音源选择、搜索与曲目行；个人队列和房间歌单分别调用本地操作与 Socket 命令 |
| 播放器     | PersonalPlayerDock、RoomDock、PersonalControls、RoomControls、PlaybackProgress、VolumeControl | 复用基础展示；个人播放器常驻，房间播放器只在房间页存在                               |
| 音频运行时 | PersonalAudioController、RoomAudioController、个人播放 hook、房间同步 hook                    | 个人控制器归应用布局，房间控制器归房间页；互斥播放，房间页卸载时清理其音频和连接     |
| AI | RoomSummary；useRoomSummaryGeneration 位于 lib/api/ai.ts | 流式展示共享总结，查询确认持久状态 |
| 历史       | HistoryPage（列表与删除）、HistoryDetail（详情）                                              | 权限凭证删除及归档导航                                                               |
| 通用反馈   | EmptyState、InlineError、LoadingSkeleton、Toaster                                                      | 查询与表单状态留在原位，短暂操作结果使用 Toast                                                 |

不是表中每个名字都要预先建文件；单次、短小逻辑留在所属组件。复用曲目行等展示组件，不用大量布尔参数把两种播放器硬合并成一个复杂组件。

## 6. 前端状态与数据流

### 6.1 状态归属

| 状态                                           | 唯一维护位置                           | 持久化                                                     |
| ---------------------------------------------- | -------------------------------------- | ---------------------------------------------------------- |
| 已提交搜索词、选择音源                         | URL                                    | 浏览器地址及历史                                           |
| 搜索、歌词、喜欢、房间大厅、历史及持久总结     | TanStack Query                         | 首版仅内存缓存，不把用户数据放公共 localStorage            |
| 会话                                           | Better Auth 客户端及服务端校验         | Session Cookie，由认证库管理                               |
| 当前房间成员、上台、消息、房间歌单、播放时间轴 | 房间页内的 room store，Socket 快照驱动 | 不持久化、不跨页保留；退出时清空，仅在当前房间页内重连校准 |
| 个人播放队列、播放器模式及面板                 | player / UI store                      | 队列首版仅内存；偏好可独立保存                             |
| 音量、用户选定主题                             | 偏好状态                               | 如实现持久化，只保存这些非敏感值                           |
| 未提交搜索、弹窗表单、聊天草稿                 | 组件状态 / React Hook Form             | 不持久化                                                   |
| Audio、Socket、AbortController、计时器         | provider / 控制器的 ref                | 不进入 DTO、数据库或持久 store                             |

普通 HTTP 数据不再复制到 Zustand；Socket 的 room store 不是服务端权威状态，断线后不能依赖本地内容进行投票或切歌。用户切换或退出时清掉上一用户的 Query 缓存和 room store。

### 6.2 当前 Query key

| 数据       | 当前 key 与查询方式                                                                                 |
| ---------- | --------------------------------------------------------------------------------------------------- |
| 真实主搜索 | ['music', 'search', source, q]；useInfiniteQuery 的 pageParam 承载 offset，每页 30 条；q 去首尾空白 |
| 真实喜欢   | ['likes', userId]；一次读取 offset=0、limit=500，所有页面共享该账号集合                             |
| 真实大厅   | ['rooms', userId, q]；15 秒刷新，默认一次读取最多 500 条摘要                                        |
| 房间内搜索 | 共用 ['music', 'search', source, q]；输入停顿 400ms 后请求，复用真实搜索分页                        |
| 真实歌词   | ['music', 'lyrics', source, source_id]；useLyrics，切歌取消过期查询                                 |
| 本人历史   | ['room-history', userId]；最多 50 条                                                                |
| 历史详情   | ['room-history-detail', userId, roomId]；总结另用 ['room-summary', userId, roomId]                  |

大厅、创建和历史 hooks 与音乐／喜欢 hooks 一起集中导出于 api-client.ts。房间实时快照不使用 Query key。

Query key 中的 userId 只用于浏览器缓存隔离，不是 API 授权依据。短期播放资源按需解析，不让旧 URL 在过期后继续复用；歌词可缓存，无歌词的成功结果与上游错误分开。

### 6.3 请求与实时更新

请求按传输层、业务模块和统一入口分工：src/lib/http.ts 定义真正的 Axios 实例（baseURL=/api）和一个响应拦截器，集中校验外壳、刷新 401 会话、转换 HttpError 及 AbortError，成功时原样返回 Axios 响应；src/lib/api/music.ts、likes.ts、rooms.ts、ai.ts、account.ts 分别维护业务请求和 hooks，经 api-client.ts 统一导出；业务请求使用原生 get／post／delete，查询传 params、POST 传对象，并显式读取 response.data.data 后返回业务数据。接口声明 ApiSuccess<T>，不通过类型断言伪装返回值，也不额外包装 Axios 方法。Axios 自动序列化对象及设置对应请求头，GET 不强制 Content-Type。http.ts 不弹提示，短暂操作反馈由业务 hooks 负责，表单和查询错误由页面展示；不自动重试或额外限制导入时长。Better Auth、AI SDK 和媒体流各自使用官方或原生传输。

1. API 客户端统一解析普通 ApiResult 和错误码，带 Cookie；不把认证库、SSE 和媒体字节当普通 JSON 处理。
   总结请求、完整结束检查和 useRoomSummaryGeneration(roomId) 集中在 src/lib/api/ai.ts，由 api-client.ts 统一导出。useCompletion 以 data 协议管理正文、加载和错误；SDK 原生解析器和 schema 确认正常结束。账号、房间和页面实例隔离，卸载、换号或换房使旧请求失效并停止接收；后台任务继续生成。内部请求处理 HTTP 错误、401 会话刷新、Retry-After、取消和网络失败。请求结束后刷新发起账号与房间的 GET 查询，以 PostgreSQL 为准；页面不传接口或保存／刷新回调，流正文不持久化、不复制进 Query。
2. 真实音乐、喜欢和房间的 useQuery、useMutation、useInfiniteQuery 按业务定义在 src/lib/api/，由 src/lib/api-client.ts 统一导出 useLikes、useAddLike、useRemoveLike、useClearLikes、useImportLikes、useMusicSearch、useLyrics、useRooms、useCreateRoom、useRoomHistory、useDeleteRoomHistory、useRoomHistoryDetail。喜欢 query key 为 likes + 当前用户 ID，未登录时不自动查询；房间加歌等无需收藏的场景可显式禁用。
3. 收藏 hooks 内置公共 onSuccess：刷新发起操作用户的喜欢缓存，显示 toast，再执行页面可选的成功回调；onError 显示操作错误，输入校验留给表单。换号后完成的旧操作不弹通知或调用新页面回调。曲目和导入参数通过 mutate(track)、mutate({ source, url }) 传入，不在 hook 闭包内绑定表单输入；所有 hooks 原样返回 TanStack Query 结果，不另外复制 data、error 或 pending 状态。
4. 页面负责 URL、输入、弹窗、播放、表单与查询错误展示；清空弹窗关闭通过 useClearLikes 的可选 onSuccess 传入，导入统计交给 toast。原始 musicApi、likesApi 仍供音频控制器和事件动作调用，Better Auth 和 Socket 传输独立维护。
5. 收藏成功更新或失效喜欢查询，搜索行的喜欢态从对应 Query 数据推导；导入后刷新容量和列表。
6. Socket 加入确认初始化 room store；广播按房间身份、播放版本、同进程递增 revision 和消息 ID 更新；重连加入可接受服务重启后的新 revision。ack 和广播不各追加一次消息。
7. 房间信息变化使大厅缓存失效或按需重查，但不把大厅摘要当作当前房间在线状态。纯房间增删操作不自动重试。

生产浏览器通过宿主机 Nginx 的同域入口访问 Web 与 `/socket.io/`，`NEXT_PUBLIC_SOCKET_URL` 构建时留空；它不能指向 `socket` 等容器服务名，运行时修改环境变量也不会覆盖已生成的浏览器代码。AI SSE 使用同域路径，Nginx 禁止缓冲，配置见 [部署指南](部署指南.md)。本地仍使用 localhost 的独立 Web／Socket 端口。

### 6.4 播放模式状态

当前个人 store 使用 roomActive 与 playing 区分房间互斥和个人播放，另有 loading、error、queue、position 等状态；useRoomSession 的 connection 为 joining / joined / reconnecting，错误独立保存，不用一个播放布尔值承担连接状态。

- 从房间页进入搜索或喜欢时执行退房清理；其他业务页不保留本标签页的房间连接，点击个人播放直接进入 personal。
- 个人播放器提供顺序／随机切换。顺序模式按队列循环；随机模式保留当前歌曲在队首并打乱其余曲目，再按该队列循环，一轮不逐首重新随机。切回顺序时恢复本次播放来源列表的初始顺序，已移除项不恢复；切换不重置当前进度、播放／暂停状态。
- 个人播放列表支持鼠标及键盘手柄排序；当前曲目的拖拽与移除均禁用，store 也拒绝移动当前曲目。移动其他歌曲只更新顺序和当前索引，保持播放进度及播放／暂停状态；队列、模式和排序仅在会话内存中保存。
- 个人音频控制器异步解析临时资源并取消过期请求，媒体元数据校准实际播放时长。不能完整播放的曲目跳过，整轮失败停止；服务或限流错误暂停反馈。暂停过久地址过期时重新解析并保留当前位置。
- 个人播放中加入房间：加入成功后停止个人音频，切到 room；密码错误或加入失败不提前破坏个人播放。
- 离开房间页、显式离开或切换 roomCode 时，停止原房间音频、取消待完成请求与重连、发送 room:leave 并移除订阅、关闭本页连接、清空房间快照；离开后不自动恢复旧个人队列播放，也不保留返回旧房的播放器入口。
- room:leave 无法送达时由连接断开处理离线；其他标签页仍在该房间时按其剩余连接判断用户在线，不因本页退出而解散房间。重新进入房间页需重新加入，不复用旧成员快照。
- 切歌、异步解析资源和加载完成都检查当前模式与曲目身份；房间模式额外检查版本，防止旧请求完成后覆盖新节目。
- 个人播放器允许暂停与进度调整；拖动进度条只更新滑块和时间预览，松手后才定位音频，拖动期间继续原位置播放；切歌清空未提交的预览，音量调整仍实时生效。房间播放器进度只读，只提供当前权限允许的切歌或投票。

- components.json 使用 base-nova，底层依赖 @base-ui/react；复用官方 shadcn/tailwind.css 的状态变体及 tw-animate-css 动画。全局样式不得覆盖控件内部隐藏输入、焦点处理或滑块布局。
- 所有 Input、Textarea 及组合输入容器在聚焦时均不绘制额外边框、光圈或轮廓，维持原有底色；错误状态仍通过字段错误和校验样式反馈，按钮、选择器等其他控件保留键盘焦点样式。
- Dialog 用于创建、导入及房间设置；队列用 Sheet，AI 结果在业务页面内展示；删除本人历史和结束房间用 AlertDialog。通过 Trigger 的 render 属性组合 Button，保留焦点返回；嵌套确认只关闭对应确认框，不复用通用 Panel 或 window.confirm。
- React Hook Form 通过 Controller 绑定 Checkbox 的 checked / onCheckedChange，Select 和 Slider 使用受控值及 onValueChange。表单按钮明确 type=submit，链接按钮使用 render + nativeButton=false，不混用 Radix 的 asChild。
- 真实歌词滚动、可读进度、虚拟歌曲列表、实时聊天是业务组件；shadcn 提供基础交互和样式，不自动提供音频同步能力。

### 8.3 桌面布局与可访问性

房间采用主区加 340px 聊天列，主区上方为成员面板，标题行是房间 AvatarGroup，下方为独立上台头像列表；再下方为当前歌曲与歌词，底部保留 96px 播放栏。按桌面视口高度伸缩，页面不滚动，仅内部内容区域滚动，不增加移动端导航、分区切换或迷你播放器。

图标按钮必须有可访问名称；菜单、弹窗可用键盘操作，焦点关闭后返回触发点。当前播放、投票和连接状态不只靠颜色区分。流式 AI 不逐字符播报给屏幕阅读器；尊重减少动画偏好，封面动画不承担必要信息。

## 9. 反馈与错误状态

短暂操作反馈统一使用 shadcn/ui 官方 Base UI Toast，在根 Providers 中挂载，位于右下方播放器上方；成功 3 秒、错误 5 秒，每条都有关闭按钮。业务 hooks 的成功／失败回调与 Socket 命令结果负责通知，http.ts 和 AI 流传输只转换并抛错。主动取消、旧账号／连接的晚到结果不通知；聊天成功、后台同步和自动媒体报告保持静默。房间设置的服务端校验错误回传表单，断线与“点击启用声音”保留原区域，不重复弹出。

| 状态                     | 页面或组件处理                                               |
| ------------------------ | ------------------------------------------------------------ |
| 首次加载                 | 在数据区域显示骨架，保留导航和播放器                         |
| 后台刷新                 | 保留已有结果，局部显示轻量请求状态                           |
| 401                      | 停止敏感操作、清理会话数据并跳登录，不无限重试               |
| 403 / 总结凭证被删       | 告知无权访问，回历史；不展示缓存正文                         |
| 409 / 已在其他房间       | 确认后才发 room:switch，普通错误不默认弹确认                 |
| 429                      | 按 retryAfterSeconds 或 Retry-After 提示等待，不自动快速重试 |
| 503 / AI_BUSY            | 提示全站生成名额已满，稍后手动重试，不自动排队               |
| 501                      | 明确能力未接通，不表现为无搜索结果                           |
| 音源不可播放 / 502 / 504 | 曲目或列表内展示可操作错误，不影响已播放的另一首             |
| 无歌词                   | 显示简洁空态；上游失败显示错误和按需重试                     |
| Socket 重连中            | 保留快照、禁止命令，恢复后校准                               |
| 房间结束 / 被踢          | 停止房间音频、清理状态、给出返回大厅入口                     |
| 归档过期                 | 清理对应查询，回历史，不保留过期正文                         |

每个错误只由一个层级负责展示，避免全局 toast、表单错误和页面 Alert 同时重复。手动切歌、导入、总结和清理等写操作不因网络中断盲目自动重试。

## 10. 当前验证与人工验收

- 当前覆盖全部页面，账号、网易云、喜欢、Socket 房间和 PostgreSQL 历史均已接入；房间总结已接入 AI SDK；百炼实测需服务端密钥。
- 在 500 首喜欢列表、长标题、无封面、时长未知及 B 站 UP 主资料下检查行布局；TanStack Virtual 要有确定的滚动容器、稳定 item key 和合理行高，不把所有小列表都虚拟化。
- 个人播放跨页不中断；房间页离开即退房停音、取消重连，不残留播放器或订阅；个人与房间模式不重叠，登录切换不泄漏前一个账号的数据。
- 房间没有暂停和可拖动进度；多人投票、旧版本推送和音频异步完成不会错误覆盖新曲目。
- 密码错误、加入失败、自动播放被拦截、断线重连都具备独立状态；桌面窗口内聊天输入和播放操作持续可见。
- 已有真实多客户端协议、断线生命周期及媒体加载／取消测试；尚未完成多浏览器真实音乐听感、生产代理与浏览器自动播放兼容性人工验收。
- UI 不承诺毫秒级同步或真实高并发容量；实际精度、播放可用性和兼容性以端到端测试结果为准。
