# POOL 前端设计

## 1. 范围与设计状态

本文负责页面路由、导航、组件拆分、前端目录、数据归属、播放器交互及 UI 风格。

本文描述前端目标设计，第一阶段已落地使用 mock 的页面与交互代码，真实接口尚未接入；当前完成情况见 [第一阶段范围](开发阶段/01-前端交互原型.md)。仅面向桌面浏览器，不做移动端适配，顶部四个入口为搜索、喜欢、一起听、设置。

原型通过 `src/mocks/api.ts`、`src/mocks/room-session.ts` 和固定文本生成服务演示 HTTP、房间与 AI 行为；模拟登录使用浏览器会话存储，业务资料位于独立 localStorage 命名空间。下文的 Cookie Session、真实 Socket 和 Vercel AI SDK 为后续后端接入的目标，不表示本阶段已接通。

## 2. 页面路由表

采用 Next.js App Router。`(auth)`、`(app)` 只用于布局分组，不进入 URL；所有业务页面必须登录，登录和注册入口除外。

| URL | 页面文件（相对 src/app） | 导航归属 | 内容与访问规则 |
| --- | --- | --- | --- |
| / | page.tsx | 无 | 草案：已登录跳 /search，未登录跳 /login，不额外做营销首页 |
| /login | (auth)/login/page.tsx | 认证 | 邮箱＋密码登录，支持安全的站内 returnTo |
| /register | (auth)/register/page.tsx | 认证 | 邮箱＋密码注册；不主动新增第三方登录和找回密码流程 |
| /search | (app)/search/page.tsx | 搜索 | 选择音源、输入关键词、查看结果、播放或收藏 |
| /likes | (app)/likes/page.tsx | 喜欢 | 最多 500 首、播放、取消喜欢、导入网易云歌单、AI 分析 |
| /rooms | (app)/rooms/page.tsx | 一起听 | 房间大厅、搜索、创建、我的房间、进入房间历史 |
| /rooms/[roomCode] | (app)/rooms/[roomCode]/page.tsx | 一起听 | 实时听歌房、加入密码、成员、上台、歌词、聊天 |
| /rooms/history | (app)/rooms/history/page.tsx | 一起听 | 本人最多 50 条房间历史，删除本人凭证 |
| /rooms/history/[roomId] | (app)/rooms/history/[roomId]/page.tsx | 一起听 | 归档详情、总结生成与阅读，后期接入 |
| /settings | (app)/settings/page.tsx | 设置 | 当前账号、退出；主题等本地偏好按实际首版范围提供 |

静态 `/rooms/history` 不作为 roomCode；系统生成的房间号带固定前缀，避免与页面路径冲突。活动房使用 code，历史详情使用 roomId，结束房不再作为实时房间加入。

搜索示例：`/search?source=netease&q=ALIVE`。音源、已提交关键词及适合分享的筛选进入 URL；实时进度、密码、未发送消息、用户凭据不进入 URL。offset 可随搜索分页维护，喜欢与房间历史的局部滚动无需强制编码到地址。

未登录访问业务页跳至登录；会话失效时清理用户私有缓存、停音并断开 Socket，再进入登录页。returnTo 仅允许站内路径。页面布局鉴权不替代 API 或 Socket 鉴权。

## 3. 导航与全局布局

### 3.1 桌面布局

```text
┌────────────────────────────────────────────────────────────┐
│ POOL        搜索    喜欢    一起听    设置             头像 │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                     当前业务页面                           │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 封面 / 歌曲       播放控制 / 进度          音量 / 队列      │
└────────────────────────────────────────────────────────────┘
```

- 顶部导航固定在视口顶部，高度 60px，不随页面滚动；主体预留同等顶部空间，避免遮挡内容。导航选中项为黑色文字与下方 #42a5f5 横线，不使用选中底色。房间详情与历史页都归属“一起听”；弹窗遮罩及内容层级高于导航。
- 底部播放器固定高度 96px，内部内容使用居中容器统一排版；页面稳定保留滚动条占位，打开播放列表不改变播放栏的横向位置或 padding。普通页面为播放栏预留空间，内容不被遮挡。
- 播放栏封面为 49×49px，个人主播放按钮为 33×33px，三区间距 35px；个人控制按钮与进度之间留 6px，房间操作与进度之间留 9px，元素尺寸与栏高配套。
- 普通页建议最大内容宽度 1,280px；房间页充分使用宽度，可扩展至 1,600px。
- 个人音频控制器放在 `(app)/layout` 的常驻客户端边界；房间连接、音频控制器和播放器仅挂载在 `/rooms/[roomCode]` 页面内。
- 离开房间页即退出当前房间：停止房间音频、取消加载与重连、移除订阅并清空房间快照，不跨页面保留房间播放器。退房不等于解散房间，不删除用户房间歌单或历史记录。

## 4. 页面组成与操作

### 4.1 搜索

- 上方仅放音源选择、搜索输入和搜索按钮。当前原型的 netease、bilibili 均使用模拟数据；真实接口阶段先接 netease，bilibili 未适配时明确“暂未接入”，不伪造空搜索结果。
- 支持按 Enter 提交，关键词不为空才请求；输入阶段不直接为每次按键请求外部源。
- 结果以紧凑歌曲行展示：封面、标题、作者、时长、收藏。
- 搜索与喜欢列表默认透明底，hover、键盘聚焦和当前播放项为白底；标准行高 60px，抽屉紧凑行高 56px，虚拟列表估算行高与实际 CSS 一致。
- 行主操作为个人播放。
- 显示 source 只为区分来源；同源搜索结果不必每行重复醒目徽章。混合队列中来源可见。
- 搜索为空显示初始输入态；无匹配、上游不可用和能力未支持分别展示，不共用“暂无数据”。

### 4.2 喜欢

- 标题“喜欢”旁显示 `已收藏 / 500`；工具栏提供播放、导入歌单和 AI 分析，不增加重复说明文案。
- 默认添加时间倒序，取消收藏后从查询结果移除。达到上限时禁用新增并给出具体提示，容量仍由服务端决定。
- 导入 Dialog 只输入网易云歌单链接；提交期间显示任务状态，结果按实际接口反馈新增、重复、失败和因容量跳过的数量，未知数量不编造为 0。
- AI 分析在独立 Sheet 中逐步显示；关闭面板与是否取消请求的语义在 AI 中断方案确定后统一。未实现时不放可点击的空壳按钮。
- 音乐最多 500 首，按项目概览使用 TanStack Virtual；数据库排序和分页先确定，虚拟化不改变真实排序，也不代替接口分页。

### 4.3 一起听大厅

- 头部为房间搜索、创建入口，提供“房间历史”次级入口；不新增第五个全局导航项。
- 我的有效房间可固定在列表前，公开房以紧凑卡片展示房间名、标签、房主、人数和加入操作。卡片默认透明底，hover、聚焦及按下时使用白底，背景立即切换，不做缓入缓出过渡。
- 密码房通过房间号查找或自己的房间入口进入，不显示密码，也不把密码写进分享地址。
- 创建 Dialog 包含名称、标签、人数、上台人数和可选密码，复杂规则交给表单错误反馈。
- 创建成功进入 `/rooms/[roomCode]`，页面经 Socket 真正加入；不能把 HTTP 创建成功直接显示为“已加入”。

### 4.4 实时房间

```text
┌───────────────────────────────────────────────────────────┐
│ 房间名 / 人数                  设置（房主） / 离开房间    │
├──────────────────────────────────┬────────────────────────┤
│ 成员与上台顺序                   │                        │
│ ──────────────────────────────── │       聊天消息         │
│ 当前歌曲 / 封面                  │                        │
│             歌词                 ├────────────────────────┤
│                                  │ 输入消息 / 发送        │
├──────────────────────────────────┴────────────────────────┤
│ 当前曲目      只读进度 / 切歌或投票       音量 / 我的歌单  │
└───────────────────────────────────────────────────────────┘
```

- 初次加载先展示加入状态；需要密码时显示密码表单，加入成功才创建房间数据投影。
- 房间页只提供一个“离开”按钮返回大厅并执行退房清理，不重复显示返回图标，不提供手动重新连接按钮；加载及密码输入阶段也使用同一个离开语义。
- 成员区使用同一面板、两份独立列表：“房间成员”标题右侧用 shadcn/ui AvatarGroup 显示全体成员；下方仅按 stageIds 展示上台成员，头像在上、名称在下，当前播放者另显“播放中”图标与文字。听众不进入上台列表，上下台不改变房间头像组的成员数量。
- 本人通过面板按钮上下台；房主可在上台成员头像旁让其他成员下台，在房间设置的成员管理中移出成员。两类列表分别读取房间成员与上台顺序，不复用混合排序列表。
- 房间页使用导航与播放栏之间的固定可用高度，页面本身不可滚动；聊天、歌词和成员列表在各自容器内滚动，头部、聊天输入与播放操作持续可见。消息自动滚动仅作用于消息容器。
- 我的房间歌单使用双列 Sheet：左侧搜索音源和歌曲并添加，右侧展示本人的歌单、导入喜欢、打乱、清空和拖拽手柄；两列独立滚动。拖动按歌曲身份与目标位置提交房间命令，不改变当前节目、起播锚点或播放版本；断线重连期间禁用修改。每人最多 500 首，导入填满剩余额度，不将所有成员曲目做成可随意编辑的共享列表。
- 房间播放进度只读，不响应拖动；当前播放者显示“切歌”，其他成员显示投票数量和本人是否投过票，无暂停操作。
- 自动播放限制显示一个清晰的“启用声音”操作；它只解锁本地音频，不暂停或改变全房状态。
- 重连中保留最后画面但禁用依赖连接的命令，重新拿到快照后校准；被踢、切换房间、房间结束分别显示一次原因并清理旧投影。
- 聊天按消息 ID 去重，保留最近 200 条客户端消息；用户向上读消息时不强制滚到底部，有新消息时给出回到底部入口。
- 聊天单条最多 120 字符，每用户每 10 秒最多 5 条；超限显示等待提示，不自动重发。服务端每房最多保留最近 10,000 条，与客户端 200 条和 AI 输入 12,000 字符分别计算。
- 进入房间时简短告知“聊天可能用于房间总结，最多保留最近 10,000 条，房间结束满 7 天清理”；不在每条消息下重复提示。
- 房主离开后的身份流转沿用旧项目；房主只拥有活动房间操作权限，结束后的总结不区分房主与普通参与者。

### 4.5 房间历史与总结（后期）

- 历史列表使用透明底紧凑行，hover 与键盘聚焦时为白底，缩小条目内边距和行间距；展示房间名、最近进入时间、结束状态和有效期，最多 50 条。删除前说明会失去该总结查看权限，不会删除其他成员的总结。
- 活动房记录可返回当前房间；已结束记录进入归档页，不尝试 Socket 加入。
- 归档展示总览与总结，不展示原始聊天列表。只区分未生成、生成中、失败可手动重试和成功，不提供总结删除按钮或已删除状态。
- 任意仍持有历史凭证的参与者可手动生成；同一房间共享结果，不提供个人“重新生成一份”。
- 生成中可查询状态，禁止重复点击启动模型；成功后所有有历史凭证的参与者共享结果，不能主动删除或重新生成。删除或淘汰个人历史后失去生成、查看权限。
- 全站 AI 并发最多 10 个，满额只提示繁忙，不显示排队状态；单次最多 60 秒，超时或输出截断展示未完成，不假装成功，允许额度内手动重试。
- 结束满 7 天按过期页处理；历史列表移除记录，详情页 410 / 清理后 404 均给出返回历史入口。

### 4.6 设置与认证

- 设置仅呈现已落地的账号信息、退出与本地偏好
- 登录使用邮箱＋密码，注册填写邮箱、密码及需要的展示名；使用简洁表单、字段错误和提交反馈，密码不写 URL、日志和持久 store。

## 5. 组件拆分与职责

```text
RootLayout
├─ GlobalStyles
└─ AppLayout（业务页面共享，服务端检查会话）
   └─ ClientProviders
      ├─ QueryProvider
      ├─ PersonalAudioController（个人播放常驻）
      └─ AppShell
         ├─ TopNav
         ├─ PageContent
         │  └─ RoomPage（仅房间路由）
         │     └─ RoomSessionProvider（连接与快照，随页面卸载）
         │        ├─ RoomContent
         │        ├─ RoomAudioController（加入成功后启用）
         │        └─ RoomPlayerDock
         ├─ PersonalPlayerDock（加入房间期间隐藏）
         └─ GlobalFeedback
```

| 组件组 | 拆分建议 | 职责边界 |
| --- | --- | --- |
| 布局 | AppShell、TopNav、UserMenu | 导航与尺寸，不直接解析音源资料 |
| 音乐 | SourceSelect、SearchForm、TrackList、TrackRow、TrackActions | 接收统一 TrackDto 和操作回调，不包含平台专属字段判断 |
| 喜欢 | LikesToolbar、ImportPlaylistDialog、ImportResult | 收藏容量及导入反馈，API 逻辑在业务 hooks |
| 大厅 | RoomSearch、RoomList、RoomCard、CreateRoomDialog | HTTP 房间摘要，不保存当前房间在线快照 |
| 房间 | RoomHeader、MemberList、StageQueue、RoomLyrics、RoomChatPanel、RoomSettingsDialog | 订阅所需字段，权限来自当前会话和快照 |
| 队列 | PersonalQueueSheet、RoomPlaylistSheet | 房间抽屉复用音源选择、搜索与曲目行；个人队列和房间歌单分别调用本地操作与 Socket 命令 |
| 播放器 | PersonalPlayerDock、RoomPlayerDock、PersonalControls、RoomControls、PlaybackProgress、VolumeControl | 复用基础展示；个人播放器常驻，房间播放器只在房间页存在 |
| 音频运行时 | PersonalAudioController、RoomAudioController、个人播放 hook、房间同步 hook | 个人控制器归应用布局，房间控制器归房间页；互斥播放，房间页卸载时清理其音频和连接 |
| AI | PlaylistAnalysisSheet、SummaryPanel、GenerationStatus | 通过 @ai-sdk/react 消费 SDK 原生流；正文和错误分开 |
| 历史 | RoomHistoryList、RoomHistoryItem、DeleteHistoryDialog | 权限凭证删除及归档导航 |
| 通用反馈 | EmptyState、InlineError、LoadingSkeleton | 简洁复用，不为每种页面建一套重复容器 |

不是表中每个名字都要预先建文件；单次、短小逻辑留在所属组件。复用曲目行等展示组件，不用大量布尔参数把两种播放器硬合并成一个复杂组件。

## 6. 前端状态与数据流

### 6.1 状态归属

| 状态 | 唯一维护位置 | 持久化 |
| --- | --- | --- |
| 已提交搜索词、选择音源 | URL | 浏览器地址及历史 |
| 搜索、歌词、喜欢、房间大厅、历史、总结状态 | TanStack Query | 首版仅内存缓存，不把用户数据放公共 localStorage |
| 会话 | Better Auth 客户端及服务端校验 | Session Cookie，由认证库管理 |
| 当前房间成员、上台、消息、房间歌单、播放时间轴 | 房间页内的 room store，Socket 快照驱动 | 不持久化、不跨页保留；退出时清空，仅在当前房间页内重连校准 |
| 个人播放队列、播放器模式及面板 | player / UI store | 队列首版仅内存；偏好可独立保存 |
| 音量、用户选定主题 | 偏好状态 | 如实现持久化，只保存这些非敏感值 |
| 未提交搜索、弹窗表单、聊天草稿 | 组件状态 / React Hook Form | 不持久化 |
| Audio、Socket、AbortController、计时器 | provider / 控制器的 ref | 不进入 DTO、数据库或持久 store |

普通 HTTP 数据不再复制到 Zustand；Socket 的 room store 不是服务端权威状态，断线后不能依赖本地内容进行投票或切歌。用户切换或退出时清掉上一用户的 Query 缓存和 room store。

### 6.2 Query key 草稿

- 搜索：`['music', 'search', source, q, offset, limit]`。
- 歌词：`['music', 'lyrics', source, sourceId]`；平台子条目完整编码在 sourceId，必要的引用版本也加入 key。
- 喜欢：`['likes', userId, offset, limit]`。
- 大厅：`['rooms', q, offset, limit]`。
- 历史：`['room-history', userId, offset, limit]`。
- 总结：`['room-summary', userId, roomId]`，需要用户维度以隔离访问权限。

Query key 中的 userId 只用于浏览器缓存隔离，不是 API 授权依据。短期播放资源按需解析，不让旧 URL 在过期后继续复用；歌词可缓存，无歌词的成功结果与上游错误分开。

### 6.3 请求与实时更新

1. API 客户端统一解析普通 ApiResult 和错误码，带 Cookie；不把认证库、SSE 和媒体字节当普通 JSON 处理。
   AI 使用 Vercel AI SDK 的 @ai-sdk/react 与原生 UI message stream；业务 hook 组织单次分析或总结请求、加载、错误和取消，不新增对话式产品流程。已有总结返回普通 JSON 时先识别响应类型，不将 JSON 交给流解析器。
2. 页面 hooks 管查询 key、提交状态和成功失效；业务组件只获取展示数据与行为，不直接遍历上游响应。
3. 收藏成功更新或失效喜欢查询，搜索行的喜欢态从对应 Query 数据推导；导入后刷新容量和列表。
4. Socket 加入确认初始化 room store；广播按房间身份、播放版本、消息 ID 更新。ack 和广播不各追加一次消息。
5. 房间信息变化使大厅缓存失效或按需重查，但不把大厅摘要当作当前房间在线状态。纯房间增删操作不自动重试。

### 6.4 播放模式状态

播放器模式建议为 none / personal / room；房间连接另有 idle / connecting / joined / reconnecting / error，不用一个 isPlaying 布尔值表达所有状态。

- 从房间页进入搜索或喜欢时执行退房清理；其他业务页不保留本标签页的房间连接，点击个人播放直接进入 personal。
- 个人播放器提供顺序／随机切换。顺序模式按队列循环；随机模式保留当前歌曲在队首并打乱其余曲目，再按该队列循环，一轮不逐首重新随机。切回顺序时恢复本次播放来源列表的初始顺序，已移除项不恢复；切换不重置当前进度、播放／暂停状态。
- 个人播放列表支持鼠标及键盘通过手柄拖拽。拖动其他歌曲只更新顺序与当前索引；拖动当前歌曲沿用旧项目从头开始，保留原播放／暂停状态。当前歌曲的移除按钮禁用，播放模式及排序只在本次原型会话内存中保存。
- 个人播放中加入房间：加入成功后停止个人音频，切到 room；密码错误或加入失败不提前破坏个人播放。
- 离开房间页、显式离开或切换 roomCode 时，停止原房间音频、取消待完成请求与重连、发送 room:leave 并移除订阅、关闭本页连接、清空房间快照；离开后不自动恢复旧个人队列播放，也不保留返回旧房的播放器入口。
- room:leave 无法送达时由连接断开处理离线；其他标签页仍在该房间时按其剩余连接判断用户在线，不因本页退出而解散房间。重新进入房间页需重新加入，不复用旧成员快照。
- 切歌、异步解析资源和加载完成都检查当前模式与曲目身份；房间模式额外检查版本，防止旧请求完成后覆盖新节目。
- 个人播放器允许暂停与进度调整；房间播放器进度只读，只提供当前权限允许的切歌或投票。

### 样式归属（当前原型）

- `app/globals.css` 仅维护字体引入、语义主题变量、基础页面与排版规则、减少动画设置；不维护业务类名或通过 `data-slot` 覆盖控件。
- `components/ui/` 维护 shadcn 基础控件的外观、焦点、尺寸及弹层限制；Input 的嵌入式／紧凑变体和 Textarea 的聊天变体由控件自身提供。
- `components/app-shell.module.css`、`page-header.module.css` 分别负责导航与页面容器、共用页头；`presentation.module.css` 提供显式引用的表单排列、空态、标签和抽屉内容布局。
- 各 feature 的 `*.module.css` 只作用于对应页面或组件。个人及房间播放栏共用 `features/player/player-dock.module.css`；两类列表共用 `features/music/sortable-queue.tsx` 与 `queue.module.css`，使用 `@dnd-kit/react` 的手柄排序与默认鼠标／键盘交互。房间双列抽屉由 `features/room/room-playlist-sheet.tsx` 与对应 CSS Module 维护。不把业务规则拆成多个全局 CSS，也不跨模块查询其他组件的内部 DOM。
- 使用明确的标题、作者、封面、按钮和状态类名，避免依赖标签顺序、`first-child`、`button:not(...)` 等结构选择器。同一组件的默认、交互和尺寸变体相邻维护。
- 跨组件颜色使用选中背景、错误前景／背景等语义变量。播放器封面与主按钮尺寸由播放器局部变量维护；歌曲行高由 TrackList 的同一份配置同时提供给虚拟列表估算和 CSS 变量，标准 60px、紧凑 56px。

## 8. UI 风格建议

### 8.1 视觉方向

采用灰阶背景、白色内容面板和 #42a5f5 点缀色。移除装饰性插画、房间配图、宣传横幅、页脚标语和氛围文案；保留歌曲封面、歌词、必要操作说明与状态反馈。按钮和卡片无边框，通过背景色、间距、hover 与选中态表达层级。

四个主页面共用 PageHeader，页头上方为 #42a5f5 英文小字（12px），下方为黑色中文大标题（28px），右侧保留必要操作：Search 搜索、Favorites 喜欢、Listen Together 一起听、Settings 设置，不附加宣传副标题。

| 语义 | 建议参考色 | 用途 |
| --- | --- | --- |
| background | #F4F6F8 | 页面背景 |
| foreground | #27313D | 主要文字 |
| card / popover | #FFFFFF | 弹层与必要的分组面板 |
| primary | #42A5F5 | 主操作、选中态和播放进度 |
| primary-foreground | #FFFFFF | 蓝底主按钮文字与图标、播放／暂停键图标 |
| muted | #EDF1F5 | 次级按钮、输入区域和弱背景 |
| muted-foreground | #768392 | 作者、时间及辅助资料 |
| primary-soft | #E9F4FE | 选中导航、当前歌曲和本人消息背景 |
| destructive | #B42336 | 删除和错误操作 |
| ring | #42A5F5 | 键盘焦点轮廓，区别于默认边框 |

参考色映射到 shadcn 语义 CSS 变量，页面不散落硬编码颜色；表中色值在真正 UI 中还需检查文字、禁用态与焦点对比度。新增 playing 等状态 token 也在全局定义。

- 正文使用 [MiSans Medium](https://ziro.oss-cn-shanghai.aliyuncs.com/fonts/MiSans-Medium/result.css)（500），标题及强调内容使用 [MiSans Demibold](https://ziro.oss-cn-shanghai.aliyuncs.com/fonts/MiSans-Demibold/result.css)（600），按外部 CSS 声明的准确 family 名接入，不合成粗体；加载期间保留系统字体回退。时间、人数和进度用等宽数字，正文 14～16px，页面标题不使用营销式超大字号。
- 间距以 4px 为基准，主要区块 16～24px；圆角以 8～12px 为主，按钮与卡片不设默认边框，浮层通过遮罩与底色区分；保留键盘焦点轮廓。
- 封面保持正方形，列表建议 40～48px；歌曲标题缺失显示“未知标题”，作者缺失省略作者行，未知时长显示“—”，不可造出 00:00。
- 搜索、喜欢、房间大厅和历史条目默认透明底，使用留白和白色 hover / 当前项表达层级，不把每首歌包装成大卡片。房间聊天与播放器靠布局区分，无需重复的功能说明标签。

### 8.2 shadcn/ui 使用边界

- 基础控件使用 shadcn/ui 官方 Base UI 版本，当前已引入 Button、Input、Textarea、Select、Checkbox、Slider、Dialog、Sheet、AlertDialog、Avatar。组件源码放 components/ui，以官方 registry 为基础调整主题和尺寸，不重写其交互实现。
- components.json 使用 base-nova，底层依赖 @base-ui/react；复用官方 shadcn/tailwind.css 的状态变体及 tw-animate-css 动画。全局样式不得覆盖控件内部隐藏输入、焦点处理或滑块布局。
- 所有 Input、Textarea 及组合输入容器在聚焦时均不绘制额外边框、光圈或轮廓，维持原有底色；错误状态仍通过字段错误和校验样式反馈，按钮、选择器等其他控件保留键盘焦点样式。
- Dialog 用于创建、导入及房间设置；队列和 AI 结果用 Sheet；删除本人历史、重置演示和结束房间用 AlertDialog。通过 Trigger 的 render 属性组合 Button，保留焦点返回；嵌套确认只关闭对应确认框，不复用通用 Panel 或 window.confirm。
- React Hook Form 通过 Controller 绑定 Checkbox 的 checked / onCheckedChange，Select 和 Slider 使用受控值及 onValueChange。表单按钮明确 type=submit，链接按钮使用 render + nativeButton=false，不混用 Radix 的 asChild。
- 真实歌词滚动、可读进度、虚拟歌曲列表、实时聊天是业务组件；shadcn 提供基础交互和样式，不自动提供音频同步能力。

### 8.3 桌面布局与可访问性

房间采用主区加 340px 聊天列，主区上方为成员面板，标题行是房间 AvatarGroup，下方为独立上台头像列表；再下方为当前歌曲与歌词，底部保留 96px 播放栏。按桌面视口高度伸缩，页面不滚动，仅内部内容区域滚动，不增加移动端导航、分区切换或迷你播放器。

图标按钮必须有可访问名称；菜单、弹窗可用键盘操作，焦点关闭后返回触发点。当前播放、投票和连接状态不只靠颜色区分。流式 AI 不逐字符播报给屏幕阅读器；尊重减少动画偏好，封面动画不承担必要信息。

## 9. 反馈与错误状态

| 状态 | 页面或组件处理 |
| --- | --- |
| 首次加载 | 在数据区域显示骨架，保留导航和播放器 |
| 后台刷新 | 保留已有结果，局部显示轻量请求状态 |
| 401 | 停止敏感操作、清理会话数据并跳登录，不无限重试 |
| 403 / 总结凭证被删 | 告知无权访问，回历史；不展示缓存正文 |
| 409 / 已在其他房间 | 确认后才发 room:switch，普通错误不默认弹确认 |
| 429 | 按 retryAfterSeconds 或 Retry-After 提示等待，不自动快速重试 |
| 503 / AI_BUSY | 提示全站生成名额已满，稍后手动重试，不自动排队 |
| 501 | 明确能力未接通，不表现为无搜索结果 |
| 音源不可播放 / 502 / 504 | 曲目或列表内展示可操作错误，不影响已播放的另一首 |
| 无歌词 | 显示简洁空态；上游失败显示错误和按需重试 |
| Socket 重连中 | 保留快照、禁止命令，恢复后校准 |
| 房间结束 / 被踢 | 停止房间音频、清理状态、给出返回大厅入口 |
| 归档过期 | 清理对应查询，回历史，不保留过期正文 |

每个错误只由一个层级负责展示，避免全局 toast、表单错误和页面 Alert 同时重复。手动切歌、导入、总结和清理等写操作不因网络中断盲目自动重试。

## 10. 原型与验收重点

- 当前原型覆盖全部页面，包含模拟历史与总结；真实历史及总结生成服务仍属后续接入，视觉保持同一系统。
- 在 500 首喜欢列表、长标题、无封面、时长未知及 B 站 UP 主资料下检查行布局；TanStack Virtual 要有确定的滚动容器、稳定 item key 和合理行高，不把所有小列表都虚拟化。
- 个人播放跨页不中断；房间页离开即退房停音、取消重连，不残留播放器或订阅；个人与房间模式不重叠，登录切换不泄漏前一个账号的数据。
- 房间没有暂停和可拖动进度；多人投票、旧版本推送和音频异步完成不会错误覆盖新曲目。
- 密码错误、加入失败、自动播放被拦截、断线重连都具备独立状态；桌面窗口内聊天输入和播放操作持续可见。
- UI 不承诺毫秒级同步或真实高并发容量；实际精度、播放可用性和兼容性以端到端测试结果为准。
