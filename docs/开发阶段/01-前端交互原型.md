# 第一阶段：可交互前端原型

当前真实账号、数据库及认证限流已接通，详见 [第二阶段交付](02-基础后端与账号系统.md)。本文维护仍使用 mock 的桌面业务范围；账号不再由模拟服务建立。

## 目标与范围

维护桌面端可交互业务原型，登录依赖已接入的真实账号服务。页面、组件和 UI 依据 [前端设计](../前端设计.md)，数据模型与响应约定依据 [服务端设计](../服务端设计.md)，业务规则依据 [项目概览](../项目概览.md)。模拟业务仅验证交互，不代表真实多人同步或模型调用。

覆盖邮箱密码登录与注册、搜索、喜欢与导入、个人播放、房间大厅、创建与密码加入、房间歌单及聊天、上下台与轮播投票、历史与总结、账号设置。四个导航入口为搜索、喜欢、一起听、设置；不适配移动端。

## Mock 边界

- 统一数据服务提供异步查询与操作；展示组件不直接维护一套假数据库，查询通过 TanStack Query，当前播放与房间投影通过 Zustand。
- 模拟接口沿用统一歌曲资料、身份、错误分类；音源选择使用预置的网易云与 Bilibili 曲目，不访问真实平台。
- 业务演示数据使用独立存储命名空间，可在设置中重置；真实会话与 mock 资料分开，mock 仅桥接安全用户信息，不保存密码，离开房间后不持久化连接、投票或播放状态。
- 本地短音频至少两段，随项目分发；实际播放、定位、暂停和切换均使用浏览器 Audio。曲目映射到演示音频，时长与本地资源一致，不声称播放平台原曲。
- 房间只有单浏览器模拟服务，预置成员、消息和队列驱动轮播；支持可控的断线、重连、投票及成员操作，不建立真实 Socket 服务。
- AI 使用固定文本分段返回，模拟生成中、取消、失败重试与成功锁定；通过独立生成服务接入，后续替换为 Vercel AI SDK 和真实模型。
- 模拟延迟、空态、失败、限流、密码错误、权限不足和容量边界均可重现，不使用随机失败。设置页提供演示场景控制及数据重置。
- 账号连接 PostgreSQL 和 Redis；音乐、房间及 AI 仍不连接真实服务。mock 业务允许使用本地存储，不代表完整服务端业务持久化。

## 功能交付

| 模块 | 本阶段交付 |
| --- | --- |
| 登录注册 | 邮箱格式、密码及展示名表单校验；真实注册登录、会话恢复、退出及站内返回路径，见第二阶段 |
| 搜索 | 音源选择、关键词匹配、加载、空结果、错误反馈、播放及收藏 |
| 喜欢 | 收藏与取消、重复去重、500 首容量、网易云链接模拟导入、长列表与 AI 分析 |
| 个人播放 | 本地 Audio、播放暂停、进度定位、音量、顺序／随机切换、可拖拽队列及切歌；跨页不断播 |
| 大厅 | 房间搜索、我的房间、创建、密码房与人数状态；进入房间后独立加入 |
| 听歌房 | 双列抽屉搜索加歌、500 首可拖拽歌单、上下台、轮播、播放者切歌、其他成员全票切歌、聊天及房主管理 |
| 房间生命周期 | 离页即退房停音、取消请求与订阅；重连校准；房主移交；空房结束场景可用预置归档演示 |
| 历史与总结 | 最多 50 条、本人删除历史、7 天过期、凭证权限、固定内容总结生成、失败重试、成功后不可删除或重生成 |
| 设置 | 账号展示、音量等本地偏好、场景切换、容量数据准备、重置及退出 |

沿用既定上限：喜欢和成员房间歌单各 500 首；聊天 120 字符、每用户每 10 秒 5 条、客户端最近 200 条、模拟存储最近 10,000 条；历史最多 50 条；总结输入预算和 AI 并发、输出与超时规则见项目概览。原型验证界面及状态分支，不声称具有实际分布式限流能力。

## 开发顺序

1. 项目配置、基础组件、桌面布局、真实账号桥接及统一 mock 业务层。
2. 搜索、收藏、导入和常驻个人播放器；加入本地音频与封面资源。
3. 大厅、房间、房间歌单、聊天、模拟成员与轮播生命周期。
4. AI 分段输出、历史归档、总结、设置及可重置演示场景。
5. 类型、代码规范、业务状态测试和生产构建检查，补充手动演示步骤。

## 验收标准

- 登录 → 搜索 → 收藏 → 本地播放 → 导入 → 大厅 → 房间加歌、上台、聊天 → 离页退房 → 历史及总结的路径可走通。
- 个人播放器支持实际播放、暂停、定位和切歌；房间进度只读，不提供暂停。
- 搜索与喜欢切换不打断个人音频；房间退出后没有残留音频、房间订阅、轮播或重连定时器。
- 两种音源、长列表、未知资料、容量边界和网络错误均有可演示状态，交互不依赖随机数触发。
- AI 正文与错误分开；失败可手动重试，总结成功后不可重新生成或主动删除；删除历史会移除对应访问权。
- 真实账号登录后可重复演示 mock 业务；重置只作用于模拟业务，不删除真实账号，浏览器不持久化密码。
- 完成适合本阶段的自动检查，不自行启动项目，用户手动启动后按 README 验证浏览器交互。

## 后续接入

保留页面、组件及 DTO，逐步替换 mock HTTP 服务、房间模拟会话和 AI 生成服务。账号基础已接入；业务表、事务、Socket.IO、音源适配及模型费用控制仍属后续，不能由模拟服务代替。

当前代码交付、已验证范围及后续业务接入点见 [阶段完成情况与后端接入准备](01-前端原型完成情况与后端接入准备.md)。

## 当前交付与验收方式

- 已建立 Next.js App Router 工程，全部页面、统一 mock 数据服务、页面级房间会话、本地音频及封面资源均已写入。
- 基础交互使用 shadcn/ui 官方 Base UI 组件：Dialog、Sheet、Alert Dialog 分别负责表单弹窗、侧栏和破坏性确认；输入、文本域、选择器、复选框及音量/进度滑块均使用对应标准组件。
- 模拟业务逻辑已有自动测试，覆盖并发收藏容量、去重导入、账号隔离、密码不落盘、历史凭证和过期、AI 并发及取消恢复、房间权限和计时器清理；本地资源测试核对音频时长及封面存在性。
- 已对用户启动的服务进行主要浏览器交互与布局检查，具体覆盖见阶段完成文档；实际听感和目标设备体验仍需用户验收，自动构建通过不代替浏览器验收。启动方式和演示步骤见 [README](../../README.md)。
- 模拟房间使用页面内事件，不具备真实多人同步；AI 为固定文案，不调用模型。真实 token 计量、日费用与接口限额、模型 60 秒超时等由后续服务端实现，原型只演示相关反馈分支。
- 原型密码房统一使用 `pool2026`，不保存用户输入密码。空房结束通过房主管理或预置历史演示，不在浏览器退出后运行后台清理。
