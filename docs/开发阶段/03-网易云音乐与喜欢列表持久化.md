# 第三阶段：网易云音乐与喜欢列表持久化

当前网易云匿名搜索、详情、歌词、个人播放和歌单导入已接入真实服务，喜欢列表保存于 PostgreSQL。Redis 承担认证及音乐请求限流、可丢弃音乐资料缓存。房间通信、房间播放、历史与 AI 继续 mock，不代表真实多人同步或模型调用。

liked_songs 的主键为 `(user_id, source, source_id)`，没有内部歌曲 ID 或独立 songs 表。新增时通过统一服务取得可信详情再保存快照；客户端不能用自带 title、extra 或 userId 覆盖平台资料或其他用户归属。播放 URL、歌词与音源 Cookie 不存入收藏。

按 added_at 倒序，再按 source、source_id 稳定排序。导入用连续服务端时间保持同批歌单顺序，已有收藏时间不变。业务表使用 timestamptz；旧 localStorage 收藏不自动导入数据库。

### JSON 请求传输

- 普通业务 JSON 客户端与网易云上游 JSON 均使用 Axios 1.21.1 的独立实例，严格解析 JSON；非 2xx 响应进入各自协议与业务错误判断，浏览器仅用一个专用响应拦截器，不增加自动重试或通用拦截器体系。
- 浏览器接口直接调用原生 Axios 方法，baseURL 统一为 /api；查询使用 params、提交使用对象，由 Axios 处理编码与请求头。拦截器成功时保留原始响应，业务接口显式取 response.data.data，页面决定如何展示错误。
- 真实页面共用 useLikes、useAddLike、useRemoveLike、useClearLikes、useImportLikes 和 useMusicSearch；操作参数通过 mutate 传入。hooks 先完成公共缓存刷新，再执行可选界面回调，直接返回 TanStack Query 结果。页面不重复定义查询键与缓存失效，表单、弹窗和播放仍属于组件；音频控制器保留原始请求函数。
- 浏览器客户端不额外设置固定超时，沿用同域 Cookie 和 AbortSignal；取消转换为 AbortError，401 触发会话刷新，保留 HttpError、业务错误码、HTTP 状态及 Retry-After。网络异常和无效响应使用统一安全提示。
- 网易云上游保持固定服务地址、匿名参数和 15 秒总期限，包括连接、响应头与完整响应体；超时映射 504，连接失败 502，HTTP／业务码限流独立映射，现有 Zod 响应校验保留。不转发 POOL Cookie，不输出凭据。
- Better Auth 使用官方客户端；浏览器播放使用 Audio；音频 Range 流代理使用原生 fetch，不套业务 JSON 响应。

## 3. 已接通接口

所有接口先读取真实 Cookie Session，再在入口校验参数；未登录返回 401。普通业务使用 ApiResult、真实 HTTP 状态码与 requestId，认证库接口保留原生协议。

| 方法与 URL | 输入及输出 |
| --- | --- |
| GET /api/music/search | source、q、offset、limit → Page<Track> |
| GET /api/music/track | source、id → Track |
| GET /api/music/lyrics | source、id → lrc、translationLrc；无歌词返回 null |
| POST /api/music/playback | source、source_id、extra → 临时 PlaybackResource |
| GET /api/music/playlist-tracks | source、url、offset、limit → 歌单资料及曲目页 |
| GET /api/music/stream | source、id、可选 Range → 媒体字节及 200／206／416，不接受任意远程 URL |
| GET /api/likes | offset、limit → Page<LikedTrack>，页面使用 limit=500 取得完整喜欢态 |
| POST /api/likes | track → item、added，首次 201，重复 200 |
| DELETE /api/likes | source、id → null，重复取消也成功 |
| POST /api/likes/import | source=netease、url → 新增／重复／失败／容量反馈 |

播放器默认使用 direct HTTPS 网易云 CDN 地址；代理接口已实现，但当前个人播放默认不走代理。播放地址每次按需解析，携带过期时间，不写 PostgreSQL，也不进入音乐资料缓存。代理只转发 Range 与必要媒体响应头，不转发用户 Cookie。

支持 music.163.com 与 y.music.163.com 的完整 playlist?id=...、/#/playlist?id=... 和移动端歌单链接；短链尚未解析，需粘贴带歌单 ID 的完整链接。导入分批读取 100 条，达到容量即停止；未读取部分无法计算准确跳过数量时 capacitySkipped=null、hasMore=true，不杜撰统计。导入总读取预算 60 秒，租约 120 秒；最终写入前在事务内重新计算容量。

## 4. Redis 缓存与限流

| 成功资料 | TTL |
| --- | --- |
| 搜索结果 | 60 秒 |
| 歌曲详情 | 300 秒 |
| 歌词（含无歌词结果） | 24 小时 |
| 歌单资料及曲目分页 | 120 秒 |

缓存键包括平台、参数和分页，当前匿名资料可共享；错误响应不缓存，私有收藏不作为共享音乐缓存。相同查询并发未命中时合并一次上游访问。

| 请求 | 维度及初始额度 |
| --- | --- |
| 搜索 | 用户 + 音源，每分钟 30 次 |
| 详情与歌词 | 用户 + 音源，共用每分钟 120 次 |
| 播放地址解析／代理 | 用户 + 音源，每分钟 30 次 |
| 歌单只读分页 | 用户 + 音源，每分钟 10 次 |
| 收藏增删 | 用户，每分钟 120 次 |
| 歌单导入 | 用户，每 5 分钟 2 次，同时最多 1 次 |
| 真实音乐上游访问 | 当前 Web 单实例共用每秒 5 次启动、并发最多 3 个 |

固定窗口计数与 TTL 由 Lua 原子执行，超限返回 429 和 Retry-After。上游自身限流映射为 502 UPSTREAM_RATE_LIMITED，与 POOL 用户 429 区分。Redis 故障时普通音乐查询退至单实例计数及无缓存访问，上游预算继续生效；批量导入返回 503，不降级成无约束任务。

## 6. 当前边界与后续

房间内搜索、连接、投票、聊天、历史和房间播放仍 mock；“导入喜欢”会读取真实收藏后放入模拟房间歌单，房间音频仍是本地演示资源。AI 歌单分析已能读取真实喜欢列表，但输出依然固定文案，不调用模型。

设置中的模拟失败、容量资料和重置不再作用于真实音乐或数据库收藏，页面不再提供向真实喜欢注入假歌的容量按钮。Bilibili 真实适配、真实 Socket 房间及 Vercel AI SDK 模型接入留到后续阶段。
