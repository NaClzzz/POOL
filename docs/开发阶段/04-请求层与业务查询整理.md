# 第四阶段：请求层与业务查询整理

当前完成 Axios 请求层拆分、音乐／喜欢业务 hooks 集中，以及搜索与喜欢列表的页面滚动。本文记录当前代码职责、调用方式和已验证范围；功能契约分别见 [项目概览](../项目概览.md)、[服务端设计](../服务端设计.md) 和 [前端设计](../前端设计.md)。真实房间边界见 [第五阶段](05-真实一起听与房间页面整理.md)，AI 原生流和业务 hooks 见 [第七阶段](07-真实歌单分析与房间总结.md)。

## 1. 请求层职责

| 位置 | 当前职责 |
| --- | --- |
| src/lib/http.ts | 真正的 Axios 实例，baseURL=/api，严格 JSON 解析与一个响应拦截器；导出 HttpError |
| src/lib/api-client.ts | 业务 API 和 hooks 的统一导出，保留页面调用入口 |
| src/lib/api/music.ts、likes.ts、rooms.ts | 按业务维护原始请求和 Query／Mutation hooks |
| src/lib/api/types.ts | 中性的 MutationSuccessOptions 成功回调约定 |
| src/contracts/domain.ts | ApiSuccess<T> 成功外壳及 ApiResult<T> 成功／失败联合，类型不改变 HTTP 响应 |
| src/server/music/adapters/netease.ts | 独立服务端 Axios 实例，网易云上游请求与平台响应转换 |

浏览器业务接口直接使用原生 get／post／delete：查询参数使用 params，POST 直接提交对象；Axios 处理参数编码、JSON 序列化和对应请求头。没有自定义 get／post／delete 转发对象或 request 包装函数。

响应拦截器只处理公共协议，不接管页面提示：

- 成功：检查响应外壳，保留原始 AxiosResponse；业务请求函数显式读取 response.data.data，喜欢列表额外读取 items。
- 业务失败：抛出 HttpError，保留 code、message、HTTP status 及 Retry-After；401 触发认证客户端刷新会话。
- 传输或 JSON 解析失败：转换为统一安全错误，不输出请求配置和凭据。
- 主动取消：转换为 AbortError，页面不将其展示为普通网络失败。

浏览器请求不额外设置固定超时，不自动重试。网易云 JSON 上游维持 15 秒总期限，包括完整响应体读取；缓存、限流和错误码仍由服务端执行。Better Auth 使用官方客户端，Audio 负责播放，音频 Range 流代理继续使用原生 fetch。

## 2. 统一导出的业务 hooks

所有 hooks 按业务定义在 lib/api/，经 api-client.ts 统一导出，直接返回 TanStack Query 原始结果，不复制 data、error、isPending，也不另造状态容器。

| Hook | 调用与职责 |
| --- | --- |
| useLikes({ enabled? }) | 当前账号喜欢列表；query key 为 ['likes', userId]，未登录或显式禁用时不自动查询，支持取消 |
| useAddLike(options?) | mutate(track) 新增收藏，公共成功回调刷新对应账号缓存 |
| useRemoveLike(options?) | mutate(track) 取消收藏，使用同一缓存刷新约定 |
| useClearLikes(options?) | mutate() 清空；缓存刷新后执行页面提供的成功动作 |
| useImportLikes(options?) | mutate(url) 导入，不捕获页面输入框内容，不主动关闭结果弹窗 |
| useMusicSearch(source, keyword) | 去除关键词两端空白，每页 30 条，offset 从 0 开始，按 hasMore 加载下一页；未登录或空关键词不自动查询 |

喜欢 mutation 的 onMutate 记录发起用户 ID；onSuccess 先等待该用户精确 query key 的缓存失效处理，再执行可选 onSuccess(data, variables)。如果请求完成时已换号，不触发当前页面的成功动作；失败不执行成功回调。HTTP 权限仍来自服务端 Cookie Session，缓存键不是授权凭据。

页面可以这样使用：

```ts
const likes = useLikes()
const addLike = useAddLike()
const importLikes = useImportLikes()
const clearLikes = useClearLikes({ onSuccess: () => setClearOpen(false) })

addLike.mutate(track)
importLikes.mutate(url)
clearLikes.mutate()
```

原始 musicApi、likesApi 请求函数继续保留，供音频控制器及事件动作直接调用；不会为了统一 hooks 把播放地址解析改成自动缓存查询。

## 3. 页面与组件边界

- 喜欢页、歌曲列表和个人播放栏复用喜欢 hooks，不再各自声明 useQuery、useMutation 或 invalidateQueries。
- 搜索页调用 useMusicSearch，保留 URL 条件、输入草稿、加载更多按钮和结果展示。
- 弹窗、表单、路由、错误显示和播放控制属于组件。清空成功关闭确认框，导入成功保留结果弹窗；这些界面动作通过回调传入，不放进请求基础模块。
- 房间大厅、创建和历史使用 lib/api/rooms.ts 的 HTTP hooks；实时房间通过 Socket，AI 使用 lib/api/ai.ts 的 useCompletion 业务 hooks；认证使用 Better Auth 客户端。
- 搜索和喜欢列表跟随页面滚动，超过 50 条使用 window 虚拟化；标准行高 60px，定位扣除列表起点。抽屉紧凑列表行高 56px，保留容器滚动。

## 4. 当前相邻能力与待对齐边界

- 已有 DELETE /api/likes/clear，清空当前 Cookie 用户收藏，返回 data:null；使用用户行事务锁及 likes-write 限流。清空喜欢不修改正在播放的个人队列。
- 当前个人播放队列禁止拖动或移除当前曲目；拖动其他曲目时保持当前歌曲和进度。
- 当前网易云适配器向 /song/url/v1 传入 level=exhigh、unblock=true，并继续检查资源可播放性及网易云 CDN 地址。上游解锁可能跨源匹配，不能将当前实现描述为已关闭解锁或已保证不跨源；该参数与不自动跨源替换的目标仍需统一，本次文档整理没有修改它。
- 账号、网易云音乐、喜欢、导入、房间、历史及 AI 均已真实接入；Bilibili 明确未支持。
