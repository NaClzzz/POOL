# 第二阶段：基础后端与账号系统

当前已落地邮箱密码账号、PostgreSQL 持久化、Cookie 会话与 Redis 认证限流。音乐与喜欢、房间与历史、AI 分别见 [第三阶段](03-网易云音乐与喜欢列表持久化.md)、[第五阶段](05-真实一起听与房间页面整理.md) 和 [第七阶段](07-AI房间总结.md)。长期契约以 [项目概览](../项目概览.md)、[服务端设计](../服务端设计.md) 和 [前端设计](../前端设计.md) 为准。

## 1. 已完成范围

| 模块 | 当前实现 |
| --- | --- |
| 基础服务 | Docker Compose 管理 PostgreSQL、Redis；固定镜像摘要、独立数据卷、健康检查、仅回环地址映射端口 |
| 数据库 | Drizzle + node-postgres 连接池、认证 schema、SQL 迁移；初始化及重复执行迁移通过 |
| 注册与登录 | Better Auth 真实邮箱密码注册／登录、唯一邮箱、密码哈希、昵称校验、错误反馈；注册成功直接登录 |
| 会话 | HttpOnly、SameSite=Lax Cookie；会话 7 天，每满一天持续使用时续期，关闭 Cookie 会话缓存，退出或过期后不能通过服务端鉴权 |
| 页面访问 | 每个业务页面入口读取服务端会话；未登录跳转登录并保留站内路径，不只依赖客户端布局 |
| 账号接口 | GET /api/account 返回当前用户安全资料与统一响应；忽略客户端 userId，不返回密码哈希或会话 token |
| 账号设置 | 展示账号、修改昵称、验证当前密码后修改密码；改密撤销其他会话，两处退出入口复用真实会话撤销 |
| 认证限流 | Redis Lua 原子计数；登录每 60 秒 5 次，注册每 60 秒 3 次，改密每 60 秒 5 次 |
| 会话同步 | 客户端刷新、窗口聚焦及每 300 秒轮询会话；换号或失效时清除私有查询、停止个人音频并卸载房间页 |
| 账号隔离 | 页面使用安全用户投影；换号后的旧异步操作不能写入新账号 |

当前不接邮件服务、邮箱验证、邮件找回、第三方登录或账号注销。邮箱是登录标识，不声称已验证；普通密码修改不能当作忘记密码找回。

## 2. 服务与依赖

- Better Auth 1.7.18，schema 由同版本 auth CLI 生成，实际表为 user、session、account、verification。认证表沿用生成器字段；liked_songs 业务表另见第三阶段。
- Drizzle ORM 0.45.4、Drizzle Kit 0.31.11、node-postgres 8.23.1。
- node-redis 6.3.1。Redis 保存认证／音乐请求计数和音乐查询缓存，会话和账号保存于 PostgreSQL，不使用 Redis secondary session storage。
- PostgreSQL 镜像摘要：`sha256:e3d24f6906d0760bf4da0dae872415391ededefad23fd471c47dc53b0ddf3c42`；当前容器版本为 18.6。
- Redis 镜像摘要：`sha256:71885d8cc6e42f2bc0aa2eb853bfc4be200b5108a46ac50e117ae1df0531fb80`；当前容器版本为 8.10.3，启用 AOF。

Compose 默认引用官方仓库；本机 .env 配置了可访问的 docker.m.daocloud.io/library/ 镜像地址，摘要与 Compose 固定值一致，未修改系统 Docker 镜像源。更换镜像通过 POSTGRES_IMAGE、REDIS_IMAGE 覆盖，并验证摘要和版本。

## 3. 代码与接口

| 位置 | 用途 |
| --- | --- |
| compose.yaml、.env.example | 本地基础服务、健康检查、持久卷及非敏感配置示例 |
| drizzle.config.ts、drizzle/ | 数据库迁移配置、SQL 及 schema 快照 |
| src/server/env.ts、db/ | 服务端配置校验、数据库连接池与认证 schema |
| src/server/auth/core.ts | 不依赖 Next 请求上下文的认证核心，可供后续 Socket 服务复用 |
| src/server/auth/handler.ts、rate-limit.ts | 原生认证协议、可信代理 IP、故障响应及 Redis 原子限流 |
| src/server/auth/session.ts | Next 页面入口的服务端会话读取 |
| src/server/account.ts、http/response.ts | 当前账号接口及普通业务 JSON 成功／失败结构 |
| src/lib/auth-client.ts、features/auth/ | 同域认证客户端、表单、会话同步、账号修改和退出 |
| src/stores/session.ts | 安全用户投影，不是认证权威，不持久化身份 |

| 方法与路径 | 协议与行为 |
| --- | --- |
| POST /api/auth/sign-up/email | Better Auth 原生注册，成功后登录 |
| POST /api/auth/sign-in/email | 原生密码登录 |
| GET /api/auth/get-session | 原生会话结果或 null，支持刷新续期 |
| POST /api/auth/sign-out | 撤销当前服务端会话并清除 Cookie |
| POST /api/auth/update-user | 当前账号修改昵称 |
| POST /api/auth/change-password | 校验当前密码，修改后撤销其他会话 |
| GET /api/account | ApiResult + 200 / 401 / 500，仅当前 Cookie 用户 |

认证入口只开放上表已实现端点，保留 Better Auth 协议，不套普通业务 ApiResult。超限返回 429 及 Retry-After；Redis 限流不可用返回 503 LIMITER_UNAVAILABLE，不降级为无限制登录。读取已有会话和退出不依赖 Redis 限流。

默认 AUTH_TRUST_PROXY=false，客户端伪造的 IP 头无效，本地请求共用按端点划分的限流桶。生产反向代理必须覆盖传入的 X-Forwarded-For，配置可信后才开启 AUTH_TRUST_PROXY=true，按代理提供的 IP 限流。计数键使用哈希，不直接保存明文邮箱或 IP。

## 4. 账号与业务权限边界

- 页面、普通 HTTP 和 Socket 分别校验服务端 Cookie Session；浏览器用户投影不是认证权威。
- 收藏、用户房间歌单及历史以真实用户主键归属；新账号的收藏和历史为空。
- 账号切换时清理私有查询、停止个人播放并退出房间，旧请求不能向新账号写入结果。
- 设置提供账号资料修改与音量偏好，不提供业务数据重置入口。
- 房间路由按页面结构排除 history；离开房间页立即退房、停音并清理连接。
