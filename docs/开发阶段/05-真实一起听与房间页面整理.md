# 第五阶段：真实一起听与房间页面整理

## 当前交付

已接通真实链路：邮箱会话 → 大厅创建／搜索 → 密码加入或确认切换 → 真实搜歌加歌／导入喜欢 → 上下台和轮播 → 同步播放、投票及聊天 → 离开／结束 → 本人历史与详情。保留既有桌面布局、shadcn/ui、双列歌单抽屉和拖拽交互。

歌单分析与房间总结使用 Vercel AI SDK 接入百炼；共享总结保存于 room_summaries，完整规则与验证边界见 [第七阶段](07-真实歌单分析与房间总结.md)。

## 进程与运行

- Web：Next.js，默认 localhost:3000；认证、普通 HTTP、数据库喜欢、外部音乐查询及音频资源解析。
- Socket：`socket-server/index.ts`，独立 Node.js + Socket.IO 4.8.4 单实例，默认绑定 127.0.0.1:3002，无 Redis adapter。
- 网易云 API：仓库内 vendor/api-enhanced 独立源码服务，默认 127.0.0.1:3001；本阶段保留既有解析配置，包括 unblock=true。
- PostgreSQL、Redis：使用现有 Docker Compose；Redis 仅负责既有认证／音乐限流和音乐缓存，不存房间权威状态。

用户在迁移后分别手动启动，不由开发代理自动启动应用：

```sh
pnpm db:migrate
pnpm music:dev
pnpm dev
pnpm socket:dev
```

后三条分别在终端运行；音源已启动时无需重复。生产 Socket 使用 `pnpm build:server` 的编译产物（`pnpm socket:start`，环境变量由运行环境提供），或生产 Compose 的独立镜像，不自动执行迁移。

.env.example 已提供 SOCKET_HOST、SOCKET_PORT、NEXT_PUBLIC_SOCKET_URL、ROOM_WEB_URL 和 ROOM_INTERNAL_SECRET。Web 和 Socket 必须读取同一独立随机密钥（至少 32 字符），不要复用认证密钥。实际密钥只在未提交 .env。浏览器 Web 与 Socket 使用相同主机名，BETTER_AUTH_URL 同时决定允许的 Origin。

健康检查：`GET http://127.0.0.1:3002/health`，200 JSON `{ok:true}`；表示进程可响应，不承诺全部依赖健康。生产构建前将 NEXT_PUBLIC_SOCKET_URL 留空，通过同域 `/socket.io/` 反向代理，启用 HTTP/1.1 Upgrade、Connection 头并将代理读超时设为覆盖心跳周期；已提供宿主机 Nginx 模板与生产 Compose，实际公网部署仍需验收，见 [部署指南](../部署指南.md)。

## 后端与持久化

迁移 `drizzle/0002_kind_satana.sql` 已生成并应用到当前开发数据库，增加七张表：

| 表 | 职责 |
| --- | --- |
| rooms | 安全房间资料、房主与创建者、在线人数投影、结束与过期时间 |
| room_members | 可重置在线投影，部分唯一索引限制每用户一个活动房间 |
| user_room_playlist_items | 用户独立房间歌单，track JSONB、itemId、排序与平台身份唯一约束 |
| room_playback_states | playback JSONB 和轮播游标，服务重启重置 idle 并递增版本 |
| room_messages | 最近一万条聊天，单条最多 120 Unicode 码点 |
| room_played_songs | 实际已起播的最近五百个节目，房间和播放版本唯一 |
| room_history | 每人最多五十条访问凭证，重复加入更新最近时间 |

HTTP 已实现大厅 GET／POST `/api/rooms`、本人历史 GET `/api/room-history`、详情 GET 和删除 DELETE `/api/room-history/[roomId]`。历史访问需仍持有本人记录且未过期，否则统一 403 ROOM_HISTORY_REQUIRED。错误密码不写历史，删除和淘汰只撤销本人凭证。

- 独立 Socket 复用 Better Auth Cookie；握手校验来源与会话，每条命令复查账号和操作权限，连接每六十秒额外复查，失效主动断开。
- 同用户多标签页只算一人；最后连接离开才退房。跨房先验证目标密码、容量再切换，并通知旧连接退出；房主最后离开时转给最早仍在线成员。
- 房间命令、自动推进和离线在房间串行执行；跨房按固定键序协调。历史、创建及用户歌单的持久修改使用用户行事务锁；数据库成功后再广播与确认。
- 用户房间歌单跨房间保留，与喜欢和个人队列独立，最多五百首；加歌置顶，轮到的歌曲移至末尾。拖拽和删除提交 itemId。
- 个人播放列表及本人房间歌单超过五十首使用虚拟列表，沿用抽屉滚动区域和 63px 行高；拖拽预览按完整列表排序，落下只提交一次，滚动时保留拖动源及焦点行。自动化覆盖五百首滚动、完整索引操作、取消及排序期间歌单更新；鼠标和键盘拖拽仍需浏览器人工验收。
- 新增加歌只接收平台引用，通过内部 POST `/api/internal/room-track`，用 `x-pool-room-secret` 委托 Web 统一音乐服务取得权威资料；Socket 不另建外部调用预算。导入从服务端 PostgreSQL 喜欢快照读取，排除未接入源／无正数时长，按剩余容量导入并返回实际新增、重复、失败、容量跳过数。
- 空房三十分钟结束，房主解散仅归档；结束满七天拒绝访问并级联清理。启动补扫，运行每分钟检查；空房结束使用原空房截止时间，停机不延长归档期。
- 重启清空在线、上台、投票和计时器，播放等待；保留有效房间、用户歌单及历史。已为空房间的原截止时间不重置。

## 服务端代码边界

- HTTP Route 只转发到 handlers.ts 的五个命名入口，再调用 Service；分页 schema 统一在 server/http/validation.ts，入口校验规则不变。
- RoomService.execute 保留串行协调、成员校验、分派和统一确认；加入、上下台、聊天、投票、媒体报告、设置及踢人使用类内私有方法。内部 resolveTrack 请求由 Service 持有，Socket 通过 sendRoomNotice 处理广播与连接退出。
- 密码、房间有效性、历史上限与访问权限归 Service；数据库读写、用户锁、设置、退出、归档和重启事务归 Repository。创建校验及历史淘汰仍在事务锁内调用业务回调。KeyedSerial 位于房间目录的 keyed-serial.ts。
- 前端 RoomCommand 位于 features/room/types.ts，避免其他组件反向引用成员组件；共用 mutation 回调类型为 MutationSuccessOptions。

## 播放与事件

完整契约以 [服务端设计](../服务端设计.md) 和 `src/contracts/room.ts` 为准；统一 ApiResult 确认，Socket 错误使用独立 RoomCommandError（业务码和可选等待秒数），不附虚构 HTTP 状态。

- `room:join`／`room:switch`／`room:sync` 及普通成功命令返回本人完整快照，含公共状态、私有歌单、最近两百条消息、serverTime、revision；离开和结束返回空快照。
- 公共事件 `room:state`、消息事件 `room:message`、私有歌单事件 `user:room-playlist` 与强退事件 `room:forced-leave` 分开。命令确认二十秒超时不重发写入，只通过 room:sync 校准。
- 按固定上台顺序播放各自歌单；当前播放者直接切歌，其他在线成员全部投票后切歌。不能暂停或拖动进度。
- 预加载四秒，权威 startedAt 为 Unix 毫秒时间；服务端按时长调度自然结束。客户端自行经 Web 解析临时 URL 和歌词，不广播、持久化播放地址。
- 加入和重连通过服务器时间校准；加载完成、启用声音、页面恢复可见时重新定位。预加载期间恢复可见不会提前播放。
- 自动播放拦截只显示启用声音；普通听众失败不改变全房节目，只有当前播放者携带正确版本与 itemId 的媒体错误才允许推进。

## 前端拆分与服务边界

- `useRoomSession`：创建页面专属 Socket 和 Zustand store，管理加入、快照、事件、命令确认、断线重连、强退和卸载。断线保留画面、停止音频并禁用命令；重连获取完整快照。拒绝旧播放版本和旧 revision，服务重启后的重新加入允许投影序号重新开始。
- `useRoomAudio`：独立管理媒体加载、取消、预加载等待、校时、音量和自动播放解锁；离开清理音频资源、请求、媒体监听及计时器。
- 房间页组合 RoomHeader（含设置）、RoomParticipants、RoomNowPlaying、RoomChat、RoomDock、RoomPlaylistSheet。聊天阅读旧消息时保留位置，新消息提供回到底部入口。
- 大厅提取 CreateRoomDialog；历史列表与 HistoryDetail 分开。普通 Query／Mutation 按业务定义在 lib/api/，经 api-client.ts 统一导出，实时快照不复制到 Query 缓存。
- 房间抽屉复用音乐查询，提交搜索表单后查询，左右列独立滚动。个人播放在加入成功时暂停，离开后不自动恢复。
- 房间资料、歌单和历史来自真实服务，歌词与音频按需从统一音乐服务解析；不依赖预置成员、消息或本地媒体资源。
- 历史详情通过 AI 业务 hook 生成共享总结，并查询数据库中的生成状态和保存结果；设置仅提供账号与音量偏好。

## 验证与验收边界

已完成以下自动化验证，未启动 POOL 应用：

- 类型检查、ESLint、Prettier 和生产构建通过；单元测试 79 项、账号／音乐／房间集成 35 项通过。集成验证使用临时隔离的 PostgreSQL／Redis，结束后移除测试容器；本轮未重新运行真实网易云 live 测试。
- 真实 Socket.IO 多客户端 + PostgreSQL／Redis 集成测试：鉴权与来源、密码、人数、设置权限、同房多连接、跨房切换、房主转移、强制下台、踢人、轮播、投票、聊天限流、歌单并发容量、排序、清空及旧节目错误报告。
- 分层回归：同用户并发创建只成功一次、密码房按完整房间号检索、分页超限仍返回参数错误；独立 KeyedSerial 验证共享键顺序、无关键并行、失败后继续执行及退出排空。
- 持久历史：错误密码无记录、数据库最多五十条、删除仅本人、空房结束、七天立即拒绝与级联清理、服务重启重置和原空房截止保留。
- React DOM 房间会话及受控媒体事件：旧状态拒绝、超时只校准、账号切换、卸载、晚到加入忽略、延迟解析后的定位、切歌取消、自动播放解锁、断线停音和计时器清理。
- 房间集成使用随机数据库 schema 执行迁移，避免服务启动重置开发房间；音乐上游为可控 HTTP 服务。真实网易云解析回归通过独立 live 测试验证，不用可控上游冒充真实音源。

尚需用户手动启动后进行多浏览器真实音乐同步、听感、浏览器自动播放权限、页面交互与生产反向代理验收；协议和受控媒体测试不能代替这些验收。Go／Bilibili 适配尚未实现；百炼真实模型验收见第七阶段。
