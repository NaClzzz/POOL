# 第七阶段：真实歌单分析与房间总结

## 当前交付

账号、音乐、喜欢、一起听与历史使用既有真实服务。本阶段新增百炼 AI 请求链路，移除剩余业务 mock、模拟身份同步和设置页 AI 演示／重置入口。

- 喜欢页面在 TrackList 上方内嵌歌单分析，支持流式展示、取消和重新生成。离页或切换账号取消客户端请求；分析不入库，不跨页保存。
- 已结束房间的历史详情提供生成按钮，流式展示共享总结。客户端离页后 Web 继续消费并保存；返回或其他成员打开时查询生成状态及最终正文，不恢复中断文字流。
- 每房一份总结，首次完整生成并保存后锁定，不提供删除或重新生成。生成与查看依赖本人仍持有的有效历史记录，不检查房主身份。
- 原始聊天、播放记录和共享总结均在房间结束满七天后随归档级联清理；生成成功不提前删除输入。

## 输入与模型

| 功能     | 服务端输入                                                                                                                                    | 输出                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 歌单分析 | 本人最多 500 首收藏的全部有效歌曲的歌名、歌手与专辑；不同歌曲随机候选最多 10 首，最多 5 首有效歌词，清理 LRC 后每首最多 1,000 字符            | 沿用旧项目约 400 字的自然赏析、颜色比喻和歌单内下一首推荐；最多 1,200 token |
| 房间总结 | 最新 200 条实际节目的有效歌名、歌手与专辑，保留重复播放；不同歌曲随机候选最多 10 首，最多 5 首完整原文歌词；最新 200 条完整聊天按时间顺序输入 | 约 400～600 字的音乐、话题和共同片段回顾；最多 2,000 token                  |

两类输入的 tracks 列表及歌词样本均包含 title、author、album；缺失歌手或专辑保留 null。

歌词通过统一音乐服务读取，复用缓存和共享上游预算，不逐首扣用户音乐查询额度；不附翻译。无歌词或歌词请求失败允许使用已有资料，房间歌曲与聊天均无有效内容时不启动模型。聊天不按总字符截断，模型上下文不足时明确报错。

模型指定为 qwen3.8-flash，不自动更换。提示词只在服务端构造，客户端不提交权威歌单、聊天或自定义提示词。资料中的指令按数据处理，不作为模型任务指令，不输出思考过程。

依赖锁定为 ai 7.0.173、@ai-sdk/react 4.0.177、@ai-sdk/openai-compatible 3.0.92。

## 接口与职责

| 接口                                 | 行为                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| POST /api/ai/liked-playlist-analysis | 按 Cookie 读取本人真实收藏，返回 SDK 原生 UI message stream                                 |
| GET /api/rooms/[roomId]/summary      | 校验有效凭证、房间结束及期限，返回 RoomSummaryDto，并恢复超期生成状态                       |
| POST /api/rooms/[roomId]/summary     | 事务认领共享生成资格；新任务返回原生 SSE，已成功结果返回普通 ApiResult<RoomSummaryDto> JSON |

RoomSummaryDto 包含 roomId、status、content、errorCode、generatedAt、expiresAt；status 为 idle / generating / failed / succeeded。只有 succeeded 返回持久正文，不暴露触发用户或内部尝试标识。

- src/server/ai/handlers.ts：鉴权入口后的生成管线、准备期限、流响应与安全错误。
- service.ts：访问权限、资格恢复、输入组织；repository.ts：用户／房间事务锁、最新输入查询和条件回写。
- provider.ts：按需校验模型配置与安全错误映射；prompts.ts：提示词和歌词抽样；runtime.ts：单实例并发与 Redis Lua 额度。
- src/features/ai/use-ai-generation.ts：真实 SDK 的单次请求、文字、错误、取消及卸载清理；不新增对话式产品流程。
- transport.ts：流开始前的普通 JSON 错误和已有结果识别；SSE 仍由 SDK 原生解析。普通持久状态查询位于 src/lib/api/ai.ts，通过 api-client.ts 导出 useRoomSummary。

总结使用 room_summaries 表和 0003_puzzling_lockjaw.sql 迁移。事务先锁用户、再锁房间，检查本人历史与总结状态后认领；完成写入检查房间期限、attempt_id、generating 和资格期限，防止旧尝试覆盖新结果。删除本人历史仅撤销本人访问，不删除共享结果。

## 限额与生命周期

- 两类功能分别按触发用户每分钟 1 次、每 24 小时 10 次计数；总结跨房间累计。仅实际启动模型时计次，模型失败和手动重试也计入；返回已有总结不计次。
- Redis Lua 同时检查分钟与日窗口，通过后一起增加；拒绝请求不额外消耗另一窗口额度。Redis 不可用返回 503 LIMITER_UNAVAILABLE。
- Web 单实例合计最多 10 个任务，每用户最多 1 个歌单分析、每房最多 1 个总结；满额直接拒绝，不排队。
- 资料准备最多 30 秒，模型调用最多 60 秒，不自动重试。超时、取消、空结果、输出截断或保存失败均不标记成功；流正文不拼接错误文字。
- 总结资格 120 秒失效，进程中断后查询或再次触发可恢复失败并允许手动重试；没有独立 worker 或持久任务恢复。
- 生成中的总结每两秒查询状态。前端只以持久查询确认成功，流文字不复制进 Query 缓存；错误或权限失效时不继续展示缓存正文。
- 日志只记录请求编号和安全错误码，SDK 默认原始上游错误日志关闭；不记录提示词、聊天、密钥或供应商完整响应。

## 配置与运行

在未提交的 .env 中配置 DASHSCOPE_API_KEY；DASHSCOPE_BASE_URL 和 DASHSCOPE_MODEL 的示例见根目录 .env.example。默认使用用户指定的百炼兼容接口和 qwen3.8-flash。

未配置密钥时只对 AI 返回 AI_NOT_CONFIGURED，其余业务不受影响。本阶段已生成并执行新增迁移；其他环境执行 pnpm db:migrate。应用由用户手动启动，本阶段未自行启动 Web、Socket 或音乐源码服务。
