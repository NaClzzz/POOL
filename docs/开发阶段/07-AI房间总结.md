# 第七阶段：AI 房间总结

## 当前范围

AI 功能只包含已结束房间的共享总结。历史详情页提供生成按钮并流式展示，生成与查看要求本人仍持有该房间的有效历史记录，不依赖房主身份。

- 每房一份总结，完整生成并落库后锁定，其他参与者通过查询读取同一份正文，不再次调用模型或计次数。
- 离开页面只停止客户端接收，Web 继续生成并保存；返回后查询状态和最终正文，不恢复中断的文字流。
- 失败可在额度内手动重试，成功后不可主动删除或重新生成。
- 房间结束满七天，总结、原始聊天、播放记录和访问记录随归档级联清理；生成成功不提前清理输入。

## 输入与模型

服务端读取最新 200 条实际播放记录的有效歌名、歌手与专辑，保留重复播放，按时间顺序组织。不同歌曲随机抽样，最多尝试 10 首，使用最多 5 首有效完整原文歌词；清理 LRC 标签、保留正文和换行，不截取正文、不附翻译。歌曲列表和歌词样本均含 title、author、album，缺失歌手或专辑保留 null。

聊天取最新最多 200 条完整消息，按时间顺序输入，不按总字符截断。歌词请求失败或歌词不足可使用已有资料继续生成；歌曲和聊天均无有效内容时拒绝生成，不计额度。输入超过模型上下文时明确报错，不暗中删减。

模型为服务端配置的百炼 qwen3.8-flash，不自动更换；提示词要求约 400 字、分段回顾音乐与聊天，输出最多 2,000 token。提示词和输入只在服务端构造，客户端仅提交触发动作，不上传权威资料。资料中的指令按数据处理，不输出思考过程。

依赖锁定为 ai 7.0.173、@ai-sdk/react 4.0.177、@ai-sdk/openai-compatible 3.0.92。

## 接口与代码职责

| 接口 | 行为 |
| --- | --- |
| GET /api/rooms/[roomId]/summary | 校验有效历史、结束状态与期限，返回状态和已保存正文，同时恢复超期生成资格 |
| POST /api/rooms/[roomId]/summary | 认领并生成，成功返回 SDK 原生 SSE；已有结果只发送正常结束事件，由 GET 读取正文 |

RoomSummaryDto 包含 roomId、status、content、errorCode、generatedAt、expiresAt；status 为 idle / generating / failed / succeeded，不暴露触发用户或内部尝试标识。流开始前的错误使用统一 JSON，流中的错误使用 SDK 错误事件，不追加到正文。

| 位置 | 职责 |
| --- | --- |
| src/features/ai/room-summary.tsx 与 room-summary.module.css | 历史详情的正文、生成／重试按钮及加载、查询错误展示 |
| src/lib/api/ai.ts | aiApi、useRoomSummary、useRoomSummaryGeneration(roomId)，内部请求和正常结束检查 |
| src/server/ai/handlers.ts | 权限预查、认领、资料准备、额度和专用 streamSummary；完整输出保存后才发送正常结束 |
| src/server/ai/service.ts | 有效历史权限、资格恢复和输入组织；认领返回当前尝试 ID，已有成功结果返回 null |
| src/server/ai/repository.ts | 用户／房间事务锁、最新输入查询、尝试隔离及条件回写 |
| src/server/ai/prompts.ts | 房间总结提示词、完整歌词清理和抽样 |
| src/server/ai/runtime.ts 与 provider.ts | 同房／全站并发、触发用户额度、模型配置和安全错误映射 |

前端使用 useCompletion 的 data 协议管理正文、加载和错误，通过 SDK 原生解析器和 schema 确认正常 finishReason: stop。页面经 api-client.ts 调用业务 hook，不传接口地址或保存／刷新回调。HTTP 错误转换保留 401 会话刷新、Retry-After、取消和网络失败；成功 3 秒、错误 5 秒 toast，均可关闭，取消和失效请求不通知。已有结果的空流只刷新查询。

请求按账号、房间和页面实例隔离，卸载、换号或换房使旧请求失效并停止接收；请求结束后只刷新发起账号与房间的 Query。流正文不保存到浏览器，不复制进 Query，数据库结果由 aiApi 和 useRoomSummary 查询。

room_summaries 表及既有迁移保持不变。事务先锁用户、再锁房间，认领前校验历史和总结状态；完成写入检查房间期限、attempt_id、generating 和资格期限，旧尝试不能覆盖新状态。删除本人历史只撤销本人访问，不删除共享总结。

## 限额与生命周期

- 按触发用户跨房累计，每分钟 1 次、每 24 小时 10 次。仅实际启动模型计次，失败／重试也计，准备失败、额度拒绝和读取已有结果不计。
- Redis Lua 同时检查分钟和日窗口，通过后一起增加；Redis 不可用返回 503 LIMITER_UNAVAILABLE。总结额度继续使用 summary 命名空间。
- Web 单实例最多 10 个任务，每房最多 1 个；满额直接提示繁忙，不排队，不自动重试。
- 资料准备最多 30 秒，模型最多 60 秒；生成资格 120 秒后失效，查询或再次触发时恢复为可重试失败。
- 只有模型正常完成、正文非空且保存成功才算成功；超时、空输出、断流、截断或落库失败不锁定成功。SDK 持续消费保证客户端断开不取消后台任务；进程重启不会续跑，没有独立 worker。
- 总结生成期间每两秒查询状态。权限失效或查询错误时不继续展示缓存正文。
- 日志只记录请求编号与安全错误码，不记录提示词、聊天、密钥或供应商原始响应。

## 配置与验证

模型配置见根目录 .env.example：DASHSCOPE_API_KEY、DASHSCOPE_BASE_URL、DASHSCOPE_MODEL，仅在服务端读取。未配置密钥返回 AI_NOT_CONFIGURED，其余业务可运行。既有数据库环境继续使用已提交迁移，无新增表或迁移。

本轮类型检查、Lint、格式检查、生产构建通过；136 项 Vitest 测试通过，其中 AI 输入、限流、生成、前端生命周期和传输相关 36 项。12 项 AI 集成测试使用真实 Cookie、隔离 PostgreSQL schema、Redis 与可控兼容模型接口，覆盖权限、输入边界、共享结果、跨房用户额度、并发唯一、离页后台完成、超期恢复、旧尝试、截断重试及七天清理。

测试未调用百炼真实端点；模型权限、内容质量、费用和长输入表现仍需配置后人工验收。生产代理需关闭 SSE 缓冲。应用由用户手动启动。
