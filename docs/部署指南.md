# 单机容器部署

生产使用 `compose.production.yaml`，开发仍用 `compose.yaml`。两份文件单独运行，不叠加；项目名与数据卷相互独立。宿主机运行 Nginx 和 HTTPS，容器只运行各自的应用。

## 服务与镜像

| 服务       | 构建／入口                                                                     | 通信与数据                                                       |
| ---------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| Web        | 根 Dockerfile 的 `web` 目标；Next standalone，`node server.js`                 | 宿主机 `127.0.0.1:3000`；容器内 `web:3000`                       |
| Socket     | 根 Dockerfile 的 `socket` 目标；`node --conditions=react-server dist/socket.mjs` | 宿主机 `127.0.0.1:3002`；单实例                                  |
| 网易云 API | `vendor/api-enhanced/Dockerfile`；上游 tini + `node app.js`                    | 仅容器网络 `music:3000`，不发布宿主机端口                        |
| PostgreSQL | 固定摘要的 PostgreSQL 18                                                       | `postgres:5432`，不发布端口；`postgres_data:/var/lib/postgresql` |
| Redis      | 固定摘要的 Redis 8，开启 AOF                                                   | `redis:6379`，不发布端口；`redis_data:/data`                     |
| migrate    | 根 Dockerfile 的 `migrate` 目标；`node dist/migrate.mjs`                       | tools profile，一次性执行后退出，仅接收 DATABASE_URL             |

`pnpm build:server` 使用 esbuild 将服务端入口编译为 `dist/socket.mjs` 和 `dist/migrate.mjs`；容器内的 `socket` 与 `migrate` 镜像直接复用 `prod-dependencies` 阶段安装的精简生产 `node_modules`，不再使用 `@vercel/nft` 或手写符号链接复制。生产不依赖 tsx、TypeScript 或 drizzle-kit；迁移镜像同时包含 `drizzle/` 已提交 SQL 及元数据。

Web 只复制 standalone 产物与 `.next/static`；当前没有需要分发的 public 静态资源。根 `.dockerignore` 排除第三方源码、真实环境配置、本地依赖及构建产物；音源构建使用自己的上下文及过滤规则。Web、Socket、migrate 均以 node 用户运行。每个应用只启动一个进程，不在启动脚本执行迁移。所有服务在 `compose.production.yaml` 中统一配置 `json-file` 日志轮转（单文件上限 `10m`，最多保留 `3` 个文件）。

## 首次部署

需要 Linux、Docker Engine、Compose v2.20+（或 v5）、宿主机 Nginx、域名与证书；放行公网 80／443 即可。示例命令在仓库根目录用 Bash 执行。

```sh
cp .env.production.example .env.production
chmod 600 .env.production
```

替换所有占位密码、密钥与域名。可通过 `openssl rand -hex 32` 分别生成数据库、Redis、认证密钥，不重复使用。`DATABASE_URL` 与 `REDIS_URL` 的密码必须与各服务一致；特殊字符只在连接 URL 中百分号编码，密码变量保留原值。

| 变量                                     | 用途／注入时间                                                                                              |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| BETTER_AUTH_URL                          | 浏览器公网 HTTPS 地址，例如 `https://pool.example.com`；Web、Socket 运行时使用，决定 Cookie 与允许的 Origin |
| DATABASE_URL、REDIS_URL                  | 运行时使用容器名 `postgres`、`redis`，不能使用 localhost                                                    |
| BETTER_AUTH_SECRET                       | Web、Socket 运行时共享；至少 32 字符                                                                        |
| DASHSCOPE\_\*                            | 仅 Web 运行时接收；未填 API key 时 AI 明确返回未配置，不影响其余功能                                        |
| NEXT_PUBLIC_SOCKET_URL                   | **构建时**注入 Web，生产留空，通过同域 `/socket.io/` 连接；运行时修改不能改已生成浏览器代码                 |
| WEB_PORT、SOCKET_PORT                    | 宿主机回环端口，变更需同步 Nginx upstream；容器内部端口仍是 3000／3002                                      |
| POOL_IMAGE_TAG                           | 四个本地镜像共用的发布标签，建议填写 Git 提交号以保留回退镜像                                               |
| NODE_IMAGE                               | POOL 镜像的 Node 基础镜像构建参数；默认固定版本，可覆盖为已审核的镜像或摘要                                 |
| MUSIC_NODE_IMAGE                         | 上游音源基础镜像，默认 node:lts-alpine；网络受限时可单独覆盖来源，需保持 Alpine 以支持上游 apk 命令         |

Compose 固定内部 `MUSIC_API_BASE_URL=http://music:3000`，不提供给浏览器。音源只收到 HOST、PORT 和匿名配置，不接收 POOL Cookie 或业务密钥。`ENABLE_GENERAL_UNBLOCK=false` 只是禁用上游全局开关，POOL 适配器当前 `unblock=true` 请求参数保持不变。

真实密钥不参与构建。Next 构建导入配置时会校验服务端变量，Dockerfile 使用不可用的占位值完成编译；镜像运行阶段从 Compose 取得真实环境变量，不继承构建占位环境。`.env.production` 是 Compose 插值输入，不会整份挂载／转发到容器。所有部署命令显式指定该文件，避免使用本地 `.env`。

定义当前终端的命令缩写，然后校验、构建：

```sh
dc() { docker compose --env-file .env.production -f compose.production.yaml "$@"; }
dc --profile tools config --quiet
dc --profile tools build
dc up -d --wait postgres redis
dc --profile tools run --rm migrate
dc up -d --wait
dc ps
```

必须先成功迁移，再启动 Web／Socket；`up` 不会自动执行 tools profile，也不会替你迁移。配置检查用 `--quiet`，避免完整展开密钥到终端或 CI 日志。镜像构建不要求本机安装 pnpm 或音源依赖。网络受限可覆盖数据库／Redis 镜像源并保持固定摘要；音源使用上游 Dockerfile 的 Node 镜像，需保证其拉取和依赖下载可达。

## 宿主机 Nginx

模板见 [deploy/nginx/pool.conf](../deploy/nginx/pool.conf)。放进 Nginx 的 `http {}` include 目录，替换 `pool.example.com`、证书与私钥路径，证书签发自行按所用服务管理。首次没有证书时先完成 HTTP 验证／签发，再启用 HTTPS server。

```sh
sudo nginx -t
sudo systemctl reload nginx
```

`/socket.io/` 保留原路径，转发轮询并支持 WebSocket upgrade；AI SSE（`/api/rooms/[^/]+/summary`）与音频代理（`/api/music/stream`）单独禁止代理缓冲、缓存及 gzip 且读写超时 180 秒；主站 `/` 保持默认 gzip 压缩以减小静态资源体积。Socket 120 秒超时覆盖心跳周期。模板覆盖 `X-Forwarded-For` 为真实直连 IP，生产因此启用 `AUTH_TRUST_PROXY=true`。如果 Nginx 前再加 CDN／负载均衡，先配置可信源与 real_ip，不能直接信任客户端提供的代理头。

健康检查是进程响应探针，PostgreSQL／Redis readiness 由依赖条件检查；不检测模型与网易云外部可用性，也不代替迁移检查。Docker restart 策略处理进程退出，单独 unhealthy 不会自动重启容器。

部署后手动验收注册登录、真实音乐、两浏览器房间同步、刷新／离页退房、AI 首段及时到达与总结落库。构建或协议测试不能代替公网 HTTPS、Cookie、SSE 与真实听感验收。

## 更新

先保留当前 Git 提交与镜像标签，完成下节备份。仓库提供一键更新脚本 [deploy/deploy.sh](../deploy/deploy.sh)，在服务器根目录直接执行即可完成 `git pull --ff-only`、以当前短提交号作为 `POOL_IMAGE_TAG` 构建镜像、停止旧应用并执行数据库迁移、启动服务及状态检查：

```sh
bash ./deploy/deploy.sh
```

若已在本地提前修改代码或仅需重建容器（不拉取远端），可传 `SKIP_PULL=1 bash ./deploy/deploy.sh`。也可以手动分步执行：

```sh
dc --profile tools build
dc stop socket web
dc --profile tools run --rm migrate
dc up -d --wait
dc ps
```

迁移失败时停止更新并检查，不自动启动旧进程或重复迁移。数据库迁移不是自动可逆的；回退镜像前确认旧版本兼容新 schema，否则从备份恢复。Socket 重启清空在线／上台／投票和播放锚点，用户需重连并重新上台。Web 停止宽限 100 秒，用于等待已有 AI 任务；强制停止、崩溃或超时仍可能令生成失败，按既有资格恢复规则处理。

停止使用 `dc stop`，恢复使用 `dc up -d --wait`。`dc down` 保留数据卷；**不要执行 `down -v`**，除非明确需要清空生产数据。生产数据卷不会自动继承开发库；已有数据迁移应通过备份／恢复完成。

## 轻量 CI/CD

仓库包含两份 GitHub Actions 工作流，不依赖外部容器镜像仓库：

- [.github/workflows/ci.yml](../.github/workflows/ci.yml)：对 `main` 分支推送与所有 Pull Request 自动执行 `format:check`、`lint`、`typecheck`、`test`、`build` 与 `build:server`。
- [.github/workflows/deploy.yml](../.github/workflows/deploy.yml)：在 `main` 分支 CI 成功后（或通过 `workflow_dispatch` 手动触发），通过 SSH 登录生产服务器先 `git pull --ff-only` 再执行 `SKIP_PULL=1 bash ./deploy/deploy.sh` 完成本地镜像构建与滚动更新。

启用自动部署前，需在 GitHub 仓库 Settings → Secrets and variables → Actions 中配置以下 Secrets：

| 类型   | 名称                  | 说明                                             |
| ------ | --------------------- | ------------------------------------------------ |
| Secret | `ECS_HOST`            | 服务器公网 IP 或域名                             |
| Secret | `ECS_USER`            | 登录用户名（需具备执行 `docker compose` 的权限） |
| Secret | `ECS_SSH_PRIVATE_KEY` | SSH 私钥原文                                     |
| Secret | `ECS_SSH_KNOWN_HOSTS` | 服务器公钥指纹（启用 `StrictHostKeyChecking=yes`） |
| Secret | `ECS_DEPLOY_PATH`     | 服务器上仓库根目录绝对路径（如 `/srv/pool`）     |
| Secret | `ECS_PORT`            | 可选，SSH 端口，默认 `22`                        |

## 备份与恢复

备份文件存到仓库之外，并加密／限制权限及定期异地复制。以下使用宿主机目录 `/srv/pool-backups`，路径按服务器调整。PostgreSQL 自定义格式备份包含账号、会话、喜欢、房间和总结；角色名与配置也应妥善保存。

```sh
mkdir -p /srv/pool-backups
chmod 700 /srv/pool-backups
dc exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > /srv/pool-backups/pool.dump
```

Redis 保存限流额度及缓存，卷内保留 AOF；冷备时先停应用写入，再干净停止 Redis，复制整个 `/data`（包括 appendonlydir），不要只拷贝一个 AOF 文件：

```sh
dc stop socket web redis
redis_id=$(dc ps -aq redis)
mkdir -p /srv/pool-backups/redis
docker cp "$redis_id:/data/." /srv/pool-backups/redis/
dc up -d --wait
```

恢复数据库时先停 Socket／Web，确认目标库与备份；下面会清理并重建已有表，覆盖前必须保存当前备份：

```sh
dc up -d --wait postgres redis
dc stop socket web
dc exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner' < /srv/pool-backups/pool.dump
dc --profile tools run --rm migrate
dc up -d --wait
```

Redis 恢复需在 Redis 停止时复制备份整个 `/data` 并保持 redis 用户权限；也可不恢复可丢弃缓存，但会清空调用额度计数，应在重新开放 AI／导入请求前确认。定期在隔离环境做恢复演练，不把“存在备份文件”当作恢复已验证。
