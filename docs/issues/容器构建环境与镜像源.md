# 容器构建环境与镜像源

## 现象

- Docker Hub 认证端点在当前网络超时，无法取得 `node:lts-alpine` 和远程 Dockerfile frontend。
- 干净镜像构建未复制根 `pnpm-workspace.yaml` 时，pnpm 12 缺少仓库内 esbuild 的构建批准配置，安装失败并返回 `ERR_PNPM_IGNORED_BUILDS`。
- Windows 普通用户不能创建 Unix 风格的目录符号链接，服务端产物复制曾返回 `EPERM`。

## 处理

- POOL Dockerfile 不使用需要额外拉取的 syntax frontend；当前语法由 Docker 内置 BuildKit 支持。
- 上游 Dockerfile 保持安装／启动流程，只增加 `NODE_IMAGE` 参数；生产 Compose 用 `MUSIC_NODE_IMAGE` 单独覆盖来源。当前验证使用 `docker.m.daocloud.io/library/node:lts-alpine` 成功构建音源。仓库默认保留官方来源，镜像源可用性由部署环境确认。
- 依赖阶段显式复制 `pnpm-workspace.yaml`，复用已有 esbuild 批准与依赖策略；workspace 仅管理根包，不合并 vendor 依赖。
- 构建脚本在 Windows 使用指向输出目录的 junction，Linux 使用相对符号链接；Linux 生产产物必须在镜像内生成，不能拷贝 Windows 产物部署。

不通过提交真实环境变量、放开全部依赖脚本或修改音源接口实现来绕过以上问题。
