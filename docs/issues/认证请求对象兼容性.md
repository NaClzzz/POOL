# 认证请求对象兼容性

状态：已修复。

## 问题

Next.js 实际运行时调用 GET /api/auth/get-session 返回 500，而直接使用原生 Request 调用认证处理器的集成测试正常。

原因是认证处理器通过 `new Request(request, { headers })` 复制框架请求。框架运行时的对象可能不属于原生构造器认可的 Request 实例，被作为字符串 `[object Request]` 解析，抛出 `TypeError: Failed to parse URL from [object Request]`。错误发生在认证库处理请求之前，与数据库或 Redis 健康状态无关。

## 处理

- 在 src/server/auth/handler.ts 使用 request.url 构造请求，显式传递 method、headers、signal。
- GET／HEAD 不传 body；POST 读取原始 arrayBuffer 后传入，保持认证 JSON 请求体不变。
- 不记录 Cookie、token、密码或完整认证请求；错误日志保留错误类型。

## 验证

- tests/integration/auth.integration.ts 增加框架包装对象回归测试，分别验证 GET 会话和 POST 密码登录。
- 使用用户已启动的 Next.js 服务验证真实 HTTP 会话、注册、账号读取及退出链路；未额外启动项目。
